## 1. 项目背景与硬约束

在**不更换既有水表**的前提下，给自建出租房的 **40 块机械水表**加装光学抄表装置，
读数回传 Home Assistant。

| 约束 | 值 | 来源 |
|---|---|---|
| 不能更换水表 | — | 业主要求 |
| 表盘上方净空 | **70mm**（40 台的**最小**值，自银圈顶面起算） | 实测 |
| 单机 BOM | 目标 ≤ 50 元 | 业主预算 |
| 必须保留人工抄表 | 每月 1 日 + 租户争议时 | 业主要求 |
| 端侧完成识别 | 只回传读数 | 业主要求 |

现场：楼梯半层，每层 6 块表垂直排列；表前方净空 1 米以上；
每层一路 5V/10A 电源；楼梯间潮湿（结露风险）。

被测表：宁波埃美柯 **LXSY-15E2**，DN15 旋翼式液封冷水表，
L=165 / B=94 / H=111，G3/4B（数据取自 `amico-lxsy.pdf` 外形尺寸表）。
表盘**朝上**，5 位字轮 + 4 个指针。

> **"表盘朝上"这一条是全设计的起点。** v0.1 曾经按"表盘朝外"设计，整版报废。
> 换表型时第一件要确认的就是这个姿态。

## 2. 坐标系与命名约定

**这一节是所有几何讨论的前提，任何时候不要改动。**

```
原点 O  = 水表表盘玻璃面的中心
+X      = 沿水表体轴线（左右方向），整机左右对称
+Y      = 离墙方向（房间一侧）；吊舱、滑盖抽出、整机拆卸都在这一侧
+Z      = 垂直向上；上方净空 70mm 是全项目最紧的约束
```

关键平面（`params.Meter` 的派生量，不要手写）：

| 特征 | Z |
|---|---|
| 表盘玻璃面 | 0 |
| **银圈顶面**（= 座圈的落座面，整机高度基准） | **+4.0** |
| 蓝色固定环顶面 | +7.8 |
| 蓝盖铰链轴 | +12.8（Y = −28.25） |
| 银圈底部凸台顶 | −18.0 |
| 银圈底面 | −20.8 |
| **天花板（障碍物）** | **+74.0** |
| 镜面中心 = 镜头光轴 | +42.0 |
| 镜头前端面 | Y = +80.0 |

> 这张表 2026-09 整体下移过一次：银圈顶面从估算的 +7.0 改成实测推出的 **+4.0**，
> 天花板随之降到 +74。**改 `Meter` 的两条实测值就够了，其余全是派生量。**

### 2.1 旋转必须写出映射并逆向验算

历史上最贵的一类错误是坐标变换复合写反（DESIGN_NOTES §7.1：
整个立板飞到别处，挂在上面的东西全部悬空）。现在的规矩：

**凡是涉及旋转/换系的地方，注释里必须写全映射，并把基准点代回去验算。**

代码里三处坐标系都照做了，格式如下（摘自 `layout.board_location`）：

```
局部 +Xs (PCB 长边)  -> 全局 -Z
局部 +Ys (板厚)      -> 全局 -Y
局部 +Zs (PCB 短边)  -> 全局 -X

逆向验算：Zs = axis_zs -> X = 0 ✓；Ys = lens_face_ys -> Y = 80 ✓；Xs = axis_xs -> Z = 42 ✓
行列式检查：det = +1（纯旋转）。若写成 ez→(+1,0,0)，det = −1 —— 那是镜像，
会把 SD 卡座和排针悄悄挪到另一侧，而板子近似左右对称，看渲染图发现不了。
```

行列式那一条不是形式主义：**开发板近似左右对称，镜像错了肉眼看不出来**，
但 SD 卡座、排针、天线座的位置会全错。

## 3. 数据台账：哪些数字可信

`params.py` 里每个字段都有可信度前缀。**改设计前先看清你依赖的是哪一类。**

| 前缀 | 含义 | 改动意味着 |
|---|---|---|
| `[实测]` | 卡尺量过 | 换了一块表 / 一块板 |
| `[采购]` | 规格书 / 样本 | 换了供应商 |
| `[设计]` | 我们自己定的 | **参数搜索的主战场** |
| `[估算]` | 还没验证的假设 | 见 [§10](#10-未验证的假设)，每条都有验证方法 |

| 银圈底部凸台 | 宽 9.5 × 高 2.8 | |

>

> 实测算出来是 **4.0**，于是：

> * 天花板从 +77 降到 **+74** —— 正好是托板抬起 8mm 后的全部余量；
> * 抱箍夹持带整段下移 4.5mm（原来的上沿有 2.5mm 骑在银圈上方的空气里，

>

## 4. 光学设计

### 4.1 核心难题

表盘朝上，上方只有 70mm 净空，而相机需要 100mm 以上工作距离才有可用景深。

**解法：45° 前表面反射镜折叠光路。**

```
表盘 ──垂直上行 42mm──> 45° 反射镜 ──水平前行 80mm──> 镜头
```

总光程 **122mm**，但竖直方向只占用约 60mm；相机与电子件全部移到 +Y
（有 1 米净空），完全不占稀缺的竖直空间。

### 4.2 虚拟相机 —— 全部光学计算的基础

把镜头对 45° 镜面做镜像：

```
L  = (0, lens_face_y, mirror_z) = (0, 80, 42)
镜面：z − y = mirror_z，反射面法线 n = (0, 1, −1)/√2
L' = L − 2·((n̂·L − d)/|n̂|)·n̂ = (0, 0, mirror_z + lens_face_y) = (0, 0, 122)
```

**虚拟相机正悬在表盘中心上方 122mm 处，垂直向下看。**

于是"表盘上某点能不能被看到"退化成：**从该点连一条直线到 (0,0,122)**，
看它与镜面的交点是否落在镜片上、两段路径是否被挡。
三维折叠问题降成两段直线求交 —— `optics.py` 全部计算都基于这个等价。

反射方向验算（写出来接受检查）：

```
d_in = (0,0,1)（上行），n = (0,1,−1)/√2
d_out = d_in − 2(d_in·n)n = (0,0,1) + (0,1,−1) = (0,1,0)  ✓ 向 +Y 前行
```

### 4.3 光学参数与余量

| 量 | 值 | 判据式子 |
|---|---|---|
| 成像半径 ROI_R | 29 mm | 覆盖 Ø56.5 + 余量 |
| 总光程 | 122 mm | `mirror_z + lens_face_y` |
| 光锥在镜面处半径 | 19.02 mm | `roi_r·(1 − mirror_z/path)` |
| 45° 面与光锥交线 | Y ∈ [−24.95, +15.36] | 见 `Optics.ellipse_y` |
| 镜片光学需求（理想值） | 57 × 38 mm | `(y₁−y₀)·√2` × `2·beam_r` |
| **镜片采购规格** | **54 × 50 × 2 mm** | 后缘被蓝盖顶死，见 §5.1b |
| 镜片实际跨度 | Y ∈ [−20.79, +17.39] | 前缘光学余量 2.03mm（`OPT-03`） |
| **表盘可见半径（墙侧）** | **24.88 mm** | 被翻开的蓝盖挡住，`OPT-11`；主数据只需 20 |
| 镜片**有效**口径 | 45.6 mm | 50 − 2×2.2（T 型槽唇口吃掉） |
| 单字符成像 | **44.4 px** | `digit_w·px_h / (2·path·tan(HFOV/2))` |
| 景深半宽 | ±20.5 mm | `N·c·s²/f²`，f=2.77mm，N=2.4，c=4.4µm |
| ROI 半张角 | 13.37° | `atan(roi_r/path)`，需 ≤ min(HFOV,VFOV)/2 = 25.97° |

> **"我算过了"不是证据。** 上表每一行都给出了式子，
> 而且都在 `checks/optical.py` 里有对应规则。
> 历史上至少两次因为手算式子写错而推翻了正确方案（DESIGN_NOTES §7.7）。

### 4.4 反射镜采购规格

| 项 | 要求 |
|---|---|
| 类型 | **前表面反射镜（第一表面镜）** |
| 尺寸 | **54 × 50 × 2 mm**（长度上限由蓝盖决定，见 §5.1b） |
| 镀层 | 铝 + SiO₂ 保护膜 |
| 反射率 | 可见光 ≥ 88% |

**必须是前表面镜。** 普通背镀镜玻璃前后两次反射产生双像鬼影，
字轮出现重影，OCR 直接失效。镀膜面不可擦拭（只能气吹），
划伤即报废，**建议多买 2 片备用**。

> 曾经建议过"用报废机械硬盘盘片替代" —— **在这个尺寸下不成立**：
> 3.5" 盘片外径 95mm、中心孔 25mm，可用环带只有 35mm 宽，放不下 54×50，
> 而且中心孔会落在光路上。

### 4.5 眩光抑制

表盘是"Ø56.5、深 7.8mm 的井"（井口是蓝色固定环的顶面），盖着弧面玻璃 + 液封介质。
**同轴照明（板载闪光灯）必然在字轮上打出镜面高光 —— 这是几何问题，调亮度无效。**

解法：**两颗 5mm 草帽白光 LED（120° 全角）置于 (±39, 0, 17)**，射向表盘中心。

位置换过两轮，两轮都是被**别的东西**逼的，不是光学自己想动：

* 高度 30 → 20：托板支承片平推出来时要从灯座凸台上方掠过（§5.3）；
* (38,20) → **(39,17)**：指针小盘的实测范围（r ≤ 25）把眩光判据的考察点
  推到了**正对 LED 那条轴上**，(38,20) 在那里只有 21.4°，不及格。

三条约束夹出来的可行区很窄，扫描结果（全方位取最小值）：

| pos_r / pos_z | 最小反射夹角 | 掠射高度 | 座孔末端 X |
|---|---|---|---|
| 38 / 20（旧） | 21.4° ✗ | 14.9 | 47.6 |
| 38 / 17 | 25.8° | 12.6 | 47.9 |
| **39 / 17** | **27.9°** ✓ | **12.3** ✓ | **48.9** ✓ |
| 40 / 18 | 28.2° | 12.7 | 49.9 ✗ 穿出立板 |

> 方向是打架的：**要夹角就得低、要掠过固定环就得高、要更靠外就会把座孔顶出立板。**
> 这种三面夹击的参数只能扫，不能推。

| 检查 | 数值 | 判据 |
|---|---|---|
| 光线越过**蓝色固定环**内缘（ρ=28.25）时的高度 | 14.9 mm | `z(ρ) = z_led·ρ/R_led`，需 > 环高 7.8 + 3 |
| **覆盖整个表盘所需半锥角** | **41.1°** | 派生量，不是参数；灯珠标称 60° ✓ |
| 逐点照明追踪（42 点 × 18 个发光点，**只算我们的零件**） | 2.4% 被挡 | `LED-01` |
| 表盘上没有全黑点 | 42/42 | `LED-05` |
| OCR 关键区两灯可达 | 42/46（4 个指针盘缘单灯） | `LED-05-OCR`（警告级） |
| **OCR 关键区最小『反射-采集』夹角** | **38.1°** | `LED-06`，要求 >25° |
| 全表盘最小夹角（同侧最外缘） | 13.0° | `LED-07`，蓝圈/刻度区，无 OCR 数据 |

> **遮挡物清单分成两份是有意的。** `LED-01` 只算**我们自己的零件**（主体 + 托板），
> 因为蓝色固定环挡掉一部分掠射光是几何必然，不是设计缺陷；
> 把它混进"结构件遮挡率"里，那个百分比就再也没法用来判断设计好坏了。
> **判据要能区分"我们造成的"和"世界本来就这样"，否则它只能告诉你有问题，
> 不能告诉你该改谁。**

#### ★ 灯珠不是点光源 —— 这一条差点被漏掉

草帽灯是个 **Ø5 的穹顶**，穹顶**上半部分**发出的光角度更平，路径和顶点
发出的完全不同。镜片托板的支承片底边原本和灯珠顶点等高（都在 z=20），
于是：

```
按点光源追踪（只从顶点发射线）      →   0% 被挡
按真实穹顶取 9 个发光点追踪         →  46% 被挡（穹顶上半边整个被遮死）
```

**这是"检查够不够格"的问题，不是"设计对不对"的问题** —— 点光源模型下，
无论设计怎么错都查不出来。修法两条：

* 设计上：支承片底边中段（y −9~+9）抬到 z=28，做成一个**让光拱**；
  拱的 y 范围避开两个托台，承压面一点没少。
* 检查上：`LED-01` 改成按发光面取 9 个点追踪，遮挡物加上 `mirror_holder`
  （原来只查 `body`，而挡光的恰恰是托板）。

同一处还踩了第三个坑：`LED-02`（体积法）里为了避免灯座自身误报，
在灯珠周围挖了一个 Ø14 的球 —— 正好把证据一起挖没了。
**排除区域开得太大，等于把检查关掉。** 现在只挖刚好包住灯珠的 Ø5.5。

**必须对置两颗，不是冗余而是几何必需。**
LED 型号必须是 **120° 草帽型**：普通 5mm 圆头只有 15~30°，
会打出中心亮斑、四个指针全黑。

判据分两级（原因见 §5.1b 末尾）：**任何一点都不许全黑**是硬判据；
**OCR 关键区两灯可达**是警告级 —— 加上 7.8mm 高的蓝色固定环之后，
"每一点都要两灯可达"在物理上已经不可能满足了。

**关于反光**：眩光判据只看 **OCR 关键区**（字轮窗 + 四个指针盘），
那里最小夹角 46.9°，余量很大。表盘**最外缘**（同侧）只有 13° ——
现场大概率能看到一圈亮弧，但那是蓝圈/刻度区，没有 OCR 数据，可以接受。
⚠ 计算把表盘玻璃当成**平面**，实际是弧面 + 液封，反射瓣会展宽，
所以阈值取 25° 而不是卡着 13° 用。

**偏振片**：吊舱前壁留了 Ø20 × 1.2 沉孔作为对冲。默认不装；
若现场发现残余眩光，贴一片 Ø20 线偏振片 + LED 前贴一片旋 90° 即可。

### 4.6 ⚠ 画面是镜像的

光路含 **1 次反射**，传感器画面**左右翻转**。

* AI-on-the-edge 标 ROI 时看到的就是翻转后的画面，按翻转后的框；
* 如果要在固件里翻回来，OV2640 有 `set_hmirror()`，
  但**不要一边翻一边又按翻转后标 ROI**，两者只能选一个；
* `out/sensor_view.svg` 画的就是翻转后的画面，可以直接对照。

传感器长轴（1600px）到底对着全局 X 还是 Z，取决于模组内部芯片朝向，
**我们没有可信资料**。所以 `OPT-07` 的判据取 min(HFOV, VFOV)/2，
结论与朝向无关。第一台实物拍一张就能确定，确定后回来更新这一段。

## 5. 机械设计

### 5.1 三个打印件

| 件 | 体积 | 作用 |
|---|---|---|
| `body` | ≈142 cm³ | 抱箍（含座圈）+ 撑座 + 立板 + LED 座 + 镜托台 + 吊臂 + 吊舱（**单一连通实体**） |
| `mirror_holder` | ≈24 cm³ | 45° 托板 + 提手 + 两片支承片（**每月抄表整块提起**） |
| `slide_cover` | ≈8 cm³ | 竖直下滑，无螺丝 |

### 5.1b 水表的蓝色盖板 —— 一个反向约束住外购件、并且**吃掉一圈表盘**的活动件

真实的 LXSY-15E2 表盘上有一圈**蓝色固定环**（内径 = 可视表盘 56.5，外径 61.8，
高出玻璃面 **7.8mm** 实测）和一块**蓝色盖板**。光学读表要求盖板**常开**。

**它只能朝墙侧（−Y）停放**：朝房间侧翻会横在相机和 45° 镜之间，
朝左右翻会挡 LED。但墙侧正是镜片托板伸过去接表盘外缘光线的地方 ——
两者必然争地盘。

#### ★ 铰链在哪，比盖板多大重要一个数量级

上一版把铰链当成"在盖板边缘上、贴着固定环顶面"（y = −30.9, z = +5.0），
按那个模型算出来"镜片 62mm + 停放 ≥90°"就不碰。**做出来还是卡住。**

看清实物后，铰链其实架在一个凸耳上：

| | 上一版（错） | 实际 |
|---|---|---|
| 铰链 Y | −30.9（固定环**外**缘） | **−28.25**（与固定环**内**圆相切） |
| 铰链 Z | +5.0（贴着环顶面） | **+12.8**（高出环顶面约 5mm） |

盖板绕铰链转，**铰链挪多少，整片盖板就跟着挪多少**：往房间侧 2.65 + 往上 5.0，
合起来让翻开的盖板整片朝房间侧推进了约 **8mm** —— 正好是镜片托板要伸过去的那一段。

> **教训：活动件建模里，"转轴在哪"的权重远高于"件本身多大"。**
> 上一轮做过灵敏度扫描，扫的是 `cover_r` / `cover_t`（件的尺寸），
> 结论"这两个都不敏感"至今仍然成立 —— 但真正敏感的第三个量（铰链位置）
> 当时被当成已知量，**压根没进扫描范围**。
> 扫描能证伪的只有它扫过的那些维度；没扫的维度不会因为扫描做得漂亮就变可信。

现在铰链高度已经**实测**（销心高出固定环顶面 4.7mm），而且有交叉印证：
同时量了销心到**银圈**顶面 8.3mm，两者之差 3.6 与独立实测的
"银圈顶→环顶 3.8" 差 0.2mm（自检 `DIM-14`）。

对上了才把不确定度从 ±1.0 收到 **±0.3** —— 这一收直接换回约 0.7mm 可见半径。

> **把不确定度收小是要拿证据换的**，不能因为"现在是实测值了"就自动收小。
> 这里的证据是那条交叉印证，不是"我量过了"。

#### ★ 坏消息：翻开的盖板会挡掉表盘墙侧的一圈外缘

不管铰链多高、盖板停在哪个角度，翻开的盖板都是**一堵立在 y ≈ −23 处、
从 z ≈ 10 一直到 z ≈ 72 的墙**（盖板近端角离铰链只有 5.4mm，
转到哪个角度都在那个小圆上）。

表盘墙侧外缘发出的光要上行到虚拟相机，必须穿过这堵墙 —— 只有能从墙的
**下缘**钻过去的那部分才看得见：

```
光线在 y = y_cover 处的高度   z = path · (1 − |y_cover| / |y₀|)
能看见  ⇔  z < 盖板下缘 z_b
          ⇔  |y₀| < |y_cover| / (1 − z_b/path)
```

**镜片做多大、相机放多远都改变不了这一点。** 它是外购活动件的几何后果。

##### 可见半径**不是**停放角的单调函数

这一条反直觉，而且它恰好是现场唯一能操作的把手：

| 停放角 | 90° | 100° | 110° | 130° | 150° | 180° |
|---|---|---|---|---|---|---|
| 可见半径 mm | 25.4 | 25.0 | **24.9** | 25.2 | 26.3 | **29.1** |

翻到一半（110° 附近）**最糟**；翻到底（≥150°）反而完全不挡。
原因是两个量在反向变化：角度越大，盖板前沿越往房间侧挪（更糟），
但盖板下缘也抬得越高、越容易让光从底下钻过去（更好）。

现场实测正好把这两种情况都占了：

* 每组 6 台里有 **2 台**被墙挡住，只能翻到 90° 出头 → 可见半径 ≈ 25.0
* 另外 **4 台**能翻过 180° → **完全不挡**，可见半径 29.1（整个表盘）

> **只算区间端点会错过这个结论。** 判定用的是整段扫描（`layout._park_angles`）。

##### 丢的那一圈里有什么

实测指针小盘：**直径 10、盘心到表盘中心 20** → 四个小盘扫过的是
**r ∈ [15, 25]** 这条圆环。而**表盘的转向我们不知道**（水表拧到管路上
最后停在哪个角度是随机的），所以判据必须对任意转向成立 —— 按整圈算。

> 上一版把四个小盘写成猜出来的坐标 `(±14, −8/−18)`。那不但不准，
> 还**恰好避开了最糟的方位**（正对 LED 那条轴），于是眩光判据报了个很漂亮
> 的 38°，按整圈算只有 21°。**用猜的坐标做判据，等于让判据替你挑一个好结果。**

于是判据分成两档（`OPT-01` / `OPT-11` 都照这个分）：

| 档 | 范围 | 现状 | 级别 |
|---|---|---|---|
| **主数据**：字轮窗 + 四个小盘的**盘心** | r ≤ 20 | 可见 24.88，**余量 +4.9mm** | ERROR（通过） |
| 小盘**最外一圈**（刻度环的边） | r ≤ 25 | 可见 24.88，**差 0.12mm** | WARN |

> **用一条判据把两者混在一起，结论就没法指导决策** —— 报红的时候你不知道
> 是"整个盘看不见"还是"边缘少了 0.1mm"。前者要停工，后者可能根本不用管。

那 0.12mm 只影响**被墙挡住的那两台**，而且只影响小盘最外缘的刻度环。
三个办法，按代价排序：

1. 那两台把盖板**往墙侧多压一点**（90° 比 110° 好 0.5mm）；
2. **把盖板取下来**（卡在铰链销上的塑料盖；铅封在表体上，不是它）；
3. 接受只读字轮窗 —— AI-on-the-edge 本来主要就读字轮。

#### 镜片长度：现在由两头分别决定

镜片的两端由**两个毫不相干的东西**定，所以判据也必须拆成两条：

| 端 | 谁定的 | 判据 |
|---|---|---|
| **后缘**（墙侧） | 翻开的蓝盖 → 托板后端竖直切面 → 端壁 | `OPT-03B`：不比蓝盖更严即可 |
| **前缘**（房间侧） | 纯光学（光锥边界 Y = +15.36） | `OPT-03`：余量 ≥1.2mm |

推导链写在 `layout.py`：`cover_clear_y → holder_rear_cut_y → mirror_y_rear`，
再加上采购的镜长得到 `mirror_y_front`。**不许在 params 里手填中点位置** ——
那是上一版把 `mirror_center_y` 写成"光锥交线取中点"留下的坑：
后缘一让，中点跟着偏，前缘悄悄不够。

当前：**53 × 50 × 2 mm**，后缘 Y = −19.97，前缘 Y = +17.51（光学余量 2.14mm）。

#### 托板后端为什么是**竖直**切面

托板是一块沿 45° 斜面的板，两端本该是垂直于斜面的方端面。
那个"后上顶点"比镜片后缘还要朝墙侧多探出 `(2·wall + mirror_t)/√2 ≈ 5mm`，
正好撞进翻开的蓝盖。

改成一刀**竖直**切下去（`build_rear_trim`），托板后端就平行于蓝盖那面墙停住 ——
同样的让位量下镜片能多伸约 5mm，换回来的正是表盘外缘 5mm 的可见半径。

> **让零件的形状去贴合约束面，而不是整体退让。**

两个配套的细节，都是自检抓出来的：

* **T 型槽的后端不能跟着改成竖直面。** 试过，结果镜片装不进去 ——
  镜片是矩形玻璃，它的后端面本来就垂直于 45° 斜面，竖直的槽底会把玻璃的
  后-背角切掉 91mm³（`FIT-03` 当场报出来）。
  **配合面的方向由外购件决定，不能为了让壁厚数字好看就改它。**
* **离蓝盖最近的其实是玻璃的后-背角，不是托板的切面。**
  玻璃的后端面是 45° 的，它的背面那条棱会比托板的竖直切面再往墙侧探出一点。
  参数里 `holder_cover_clear = 0.8`，而**真实间隙只有 0.39mm**（`FIT-15`）。
  **给间隙起名字的时候要说清楚它是谁到谁的间隙**，否则标称值会让人放心得毫无根据。
  （0.39mm 是**最坏情况**下的值，已经含了铰链高度 ±1mm 的余量；
  按标称铰链高度算是 1.36mm。）

#### 固定环还会挡 LED 的掠射光

环高 7.8mm（不是原先估的 5mm）。同侧 LED 打向同侧外缘的掠射光必然被它切掉一段：
从 (38, 0, 20) 射向 (24, 0, 0) 的光线在 r = 28.25 处只有 6.1mm 高，低于环顶 7.8。

所以 `LED-05` 的判据从"每一点都要两灯可达"改成了两级：

* **任何一点都不许全黑**（硬判据，目前 42 点全部至少单灯可达）；
* **OCR 关键区要两灯可达**（警告级，目前 4 个指针盘缘点只有单灯）。

> **一条永远满足不了的判据比没有判据更糟** —— 它会训练出"忽略红字"的习惯。
> 发现判据物理上不可能满足时，正确做法是把它拆成"能满足的硬判据"
> 和"要盯着的警告"，而不是放宽阈值蒙混过去。

### 5.2 抱箍：整机唯一的机械接口

**曾经的致命错误**（DESIGN_NOTES §7.3）：内孔比银圈大 2.4mm，剖分缝只有 2.2mm，
完全闭合仅缩小 `2.2/π = 0.70mm`，**永远碰不到银圈**。
根源是假设了一个从未列入 BOM 的 1.2mm TPU 衬垫。

现在的方案：

| 项 | 值 | 理由 |
|---|---|---|
| 光孔 | Ø82.9（单边 +0.35） | 便于套入 |
| **16 条内棱** | 内切 Ø81.7（**单边过盈 0.25**） | 只有棱接触，局部压强高十几倍，抗转 |
| 剖分缝 | 4 mm | 留弹性张开行程 |
| 夹持带 | Z −15.5 ~ +2.0 | 高于底部凸台顶（−18.0），低于银圈顶（+4.0） |
| **座圈（内沿圆环）** | Z +4.0 ~ +6.5，内径 Ø63，墙侧开 ±55° 让位口 | **整机高度的唯一基准**，见下 |
| 夹紧螺栓 | 两颗 M4 蝶形，z = −11 / −2 | 上下受力均匀，防止带子张成 V 形 |
| **六角螺母沉槽** | −X 耳外表面，对边 7.4 × 深 3.6 | 螺母被抓死 → **单手拧紧**；现场是站在楼梯上、一手扶着整机 |
| 备用 | 前侧对称两个 Ø3.2 径向孔 | 棱纹不够时可拧 M4 自攻顶紧 |

**内棱的坑**：16 条棱里若有一条落在剖分缝内，会被切成孤立薄片。
代码里已加过滤，自检 `TOPO-01` 也会兜底。

#### ★ 座圈：内棱管不了高度

内棱解决了"转"和"掉"，**但管不了"压到多深"**：往下压多少全靠手感，
40 台装出来高度各不相同。而镜片托板的高度直接决定光程和 ROI 标定 ——
40 套高度就是 40 套标定。

解法是在抱箍内壁上、**银圈顶面那一层**长一圈向内的沿，压到沿贴住银圈顶面为止。
接触面是银圈的顶面：一个真实的、平的、和表盘平行的加工面。
从此整机的 Z 基准和表盘刚性关联，不再和拧螺栓的力气有关。

| 约束 | 值 | 为什么 |
|---|---|---|
| 内半径 > 固定环外半径 | 34.5 > 30.9 | 压到塑料环上就白做了：环会变形，而且环相对表盘的高度没人保证 |
| 径向厚度 ≤ 银圈径向厚度 | 6.6 ≤ 10.2 | 再厚就伸到银圈内孔上方**悬空**，既没支承又挡光 |
| **不能伸进 LED 掠射光路** | 内半径 ≥ ~34 | ← 这一条是加了座圈之后才冒出来的，见下 |
| 墙侧让位口 | ±55° | 让翻开的盖板穿过座圈平面（六台里四台的盖板能翻过 180°，装配时按不住） |

##### ★ 新结构件要和"看不见的东西"也对一遍

座圈第一版内半径取 31.5（紧贴固定环）。自检立刻报 `LED-02` 有用光束被侵入
**94mm³**，逐点追踪的遮挡率从 2.4% 跳到 4.4%。

原因：座圈在 z ∈ [4.0, 6.5]，而 LED 打向**对侧**表盘的光正好从这个高度
掠过**近侧**的表盘外缘 —— 光锥在这一段的外沿落在 r ≈ 33.8。
座圈伸到 31.5 就正好插进去了。

内半径收到 34.5 之后，`LED-01` 的遮挡率降到 **0.0%**（比加座圈之前的 2.4% 还好，
因为顺带也让开了原来就存在的一点遮挡）。承压环面仍有约 1570mm²。

> **座圈和光路在 Z 上重叠这件事，看渲染图完全看不出来** ——
> 它们在空间上是错开的两个环带，只有做布尔才知道。
> 加一个新结构件时，除了"会不会撞到别的零件"，还要问
> "会不会伸进光路 / 运动扫掠体"。

至于原先写的"让开没量过的铰链凸耳"——**那个理由已经不成立了**：
销实测 Ø5.7、销心高出环顶 4.7，销体在 z ∈ [9.7, 15.4]，和座圈（z 4.0~6.5）
在 Z 上根本不相交。让位口保留，但理由换成了真实的那个（让盖板通过）。

> **假设被证伪之后，要么去掉那个特征，要么换一个成立的理由。
> 不能让特征挂在一个已经不存在的理由上** —— 下一个人会照着错理由去改它。

判据：`DIM-12`（几何约束，纯算术）+ `DIM-13`（**反向**判据：整机再压 0.5mm
必须扎进银圈）。`DIM-13` 的判定区间刻意取在 z ∈ [银圈顶−0.6, 银圈顶]，
这一段内棱（顶 z = +2.0）够不到，量到的干涉一定来自座圈 ——
**反向判据要挑一个只有被测特征能到达的区域**，否则读数会被别的特征污染。

**关于"校准固化"**：银圈顶部凹台位置逐台不同，说明表头装配角度本身随机，
所以**支架绝对朝向无法也不需要统一** —— 每台 ROI 本来就要在软件里各框一次。
需要保证的只是**同一台反复拆装后角度可复现**：靠抱箍不打滑 + 托板四点销定位。

### 5.3 镜片托板：等高四点支承 + 抬起平推

每月人工抄表时镜片挡住字轮，必须移开。
方案是**只取下这块托板**，而不是移动整个悬臂（那会破坏相机对位）。

动作只有两步：**垂直上提 8mm 脱离定位销 → 沿 +Y 平推出来。**

* 每侧一片**支承片**（X 32~38，厚 6），底边是一条**水平线**（z=20）；
* 落在立板伸出的**两个等高托台**上（都在 z=20）；
* 4 根竖直销约束平面内自由度（间隙 0.2，竖直销零支撑打印）；
* 读完原路放回，ROI 不需要重新标定。

#### ★ 为什么托台必须等高 —— 本次重构最重要的一条发现

上一版按"托板底面是 45° 斜面"的直觉，把前托台放在 z=50、后托台放在 z=20，
支承结构做成"三角耳 + 两只支承脚"。

**每个零件单独看都对，静态干涉检查全过 —— 但整块托板根本拿不出来。**

抽出时，支承结构的**后**半段要扫过**前**托台，而它比前托台低 30mm：

```
后支承脚底面 z = 20，前托台顶面 z = 50
要越过去需要抬升 > 30mm，而天花板只给 11mm
```

这个错误是 `SEQ-02`（抄表流程逐点路径仿真）抓到的。
**静态干涉检查一条都报不出来** —— 因为"装得进去"和"拿得出来"是两回事。

现在两个托台等高、支承片底边水平，抬 8mm 就整体脱离，平推无阻。

| 约束 | 值 | 由谁保证 |
|---|---|---|
| 两托台等高 | 都是 z=20 | `CONS-12` |
| 支承片底边水平且与托台等高 | z=20 | `CONS-12` |
| 支承片外缘 < 立板内侧面 | 38 < 42.5 | `CONS-11` |
| 支承片外缘 < LED 灯座最内缘 | 38 < 约 37.7+ | `SEQ-02` 路径仿真 |
| 托台内伸斜面免支撑 | atan(10.5/12) = 41.2° | `CONS-13` |

#### LED 高度被可拆性拉低了

灯座凸台会伸到 X≈37，正好落在支承片平推的路径上。
所以 LED 从 z=30 降到 **z=20**：凸台随之落到 z<27，支承片抬 8mm 后
（底面 z=28）刚好从它上面掠过。

**光学上反而更好**：表盘中心入射角从 51.7° 增到 62.2°，镜面反射瓣偏得更远；
掠射高度 14.9mm 仍远大于 7mm 井深。

### 5.4 提手：为什么在两边而不在中间

托板要能被一只手提起来，但三个约束同时卡着：

* **不能加高** —— 天花板只剩约 10mm 余量，竖直提手会把提起行程吃掉；
* **不能放中间** —— 中间是 T 型槽的插入口。横穿过去会被槽切断
  （实测：托板裂成 2 个孤立实体，`TOPO-01` 当场报错），也会挡住镜片滑入；
* **不能挡光**。

所以提手做成：两片从支承片前端伸出的**水平**悬臂（X ±32~38，y 18~34，z 58~64）
+ 一根横梁（y 28~34）。径向早已跑出光锥；横梁虽然过中心，
但 z 58~64 高于该处反射光束上缘（y=32 处约 53.8）。
立板前缘只到 y=22，所以横梁所在的 y 28~34 是完全敞开的，手伸得进去。

### 5.5 镜片 T 型槽

反射面朝下，直通方槽会让镜片掉出来。改成 T 型槽：

* 深部 50.2mm 宽容纳镜片；
* 开口收窄到 45.6mm，**两侧各留 2.2mm 唇口**；
* 从局部 −Y 一端滑入（全局方向为斜向上前方）。

**局部 z 的零点定义**（改之前必读 `parts/mirror_holder.py` 顶部）：

```
局部 z = +0.8   唇口外表面
局部 z =  0     ★ 镜片镀膜面 = 光学基准面 z = y + 42
局部 z = −2.0   镜片背面
局部 z = −4.5   托板背面
```

早期版本把零点定在"托板正面"，结果实际反射面比设计平面**退后 0.8mm**，
光线追踪直接打空 —— 这是个**只有射线求交才能发现**的错误，
体积布尔和肉眼都看不出来。

**镜片是在台面上装进托板的，不在现场装。**

### 5.6 滑盖：真正的 C 型槽

**曾经的错误**（DESIGN_NOTES §7.6）：槽只约束 X，盖板可以直接向后掉出来。

现在的结构（沿 Y 从前到后）：

```
Y  ~108.75   侧壁前沿      → 约束 −Y
Y 108.75~112.2  滑槽(X±19.5)  → 盖板舌片(X±19.3)在此，约束 X
Y 112.2~114  后压边(1.8mm) → 约束 +Y
```

盖板从顶部插入，竖直下滑，槽底限位。顶部有 Ø16 手指凹槽。

**主型腔必须贯通到吊舱后表面**，不能封死后端：推荐打印姿态下
（主体绕 X 轴 +90°，+Y 朝上）封死的后端会变成 34×66mm 的大平顶悬空，
远超 15mm 桥接上限。这是 DfAM 决定的结构，不是随便开的口。

### 5.7 吊舱：靠摄像头模组自己定位光轴

不用任何额外零件固定开发板。型腔沿 +Y 分四段：

```
[前壁 3mm，Ø13 镜头孔 + Ø20×1.2 偏振片沉孔]
[摄像头方腔 9.2×9.2 —— 只夹模组本体，光轴的 X/Z 由它决定]
[深级让位槽 X±8.9 —— SD 卡座 + 排线]
[浅级让位槽 X±13.4，Z>18.8 —— 一圈贴片元件]
┃ ← PCB 前表面止挡（落在 Z<18.8 那条前侧完全干净的下缘带上）
[主型腔 —— 板卡、天线、驱动板、走线]
[滑盖]
```

板卡六个自由度：

| 自由度 | 靠什么 | 自检 |
|---|---|---|
| −Y | PCB 前表面顶在台阶上 | CONS-07 |
| **+Y** | **下缘后压唇扣住 PCB 下缘后角** | **CONS-14 / 15** |
| ±X | 两条侧向导轨（单边间隙 0.4） | CONS-08 |
| −Z | 板下缘落在承台上 | CONS-09 |
| +Z | 重力 + 泡棉 | — |
| 绕轴 | 导轨 + 承台 + 压唇 | CONS-08/09/14 |

#### ★ 板卡固定：一条几何定理，以及它逼出来的方案

**实物反馈：板卡装进去以后一摇就从 pitch 方向倒出来。而当时所有 `CONS` 检查全绿。**

先看错在哪。上一版的约束是：

* −Y：前腔台阶止挡
* +Y：**下缘后压唇**（板卡抬高 `board_lift` 推入、落下就位后扣住 PCB 下缘后角）
* +Z：**"重力 + 泡棉摩擦"**

第三行就是病根。**"重力 + 摩擦"不是约束，把它写进自由度表里就是自欺欺人。**
失效链是这样闭合的：

```
板卡能上抬 board_lift（所有让位腔都是按这个行程放大的）
  → 抬到顶时下缘压唇（高 board_lift − 0.3）刚好完全脱开
  → 上端本来就没有任何约束
  → 整块板绕下缘转出去
```

#### 定理：刚性上限位在这种装配动作下不可能成立

> **用"抬起-推入-落下"装入的板，任何长在壳体上的刚性上限位，
> 都不可能把上抬行程限制到小于压唇的高度。**
>
> 证明：压唇要让板推得进去，高度必须 < 抬升行程 L；
> 上限位要让抬起来的板推得进去，它离板上缘的距离必须 ≥ L。
> 两条一联立：可上抬行程 ≥ L > 压唇高度，恒成立。
> **与限位放在哪、做多大无关。**

所以只有两条出路：加**弹性件**，或者让最后装的那个件（滑盖）来当上限位。
这里选弹性件 —— 它在滑盖装上**之前**就生效，而"板卡掉出来"恰恰发生在那之前。

> 上一版写的"想做弹性卡扣在几何上不成立"**只对了一半**：
> 结论是对的（卡钩生根在前止挡台阶上确实只有 1.6mm 悬臂长度），
> 但**方向找错了** —— 悬臂不必生根在前止挡上。
> 从侧壁上沿 Z 向上长一根 17mm 的悬臂，空间一直都在。
> **"这个方案不成立"的结论，要说清楚是哪一种实现不成立。**

#### 现在的方案：两侧各一根弹性悬臂，头上带两个特征

```
z = pcb_z1 + 0.4 + 2  ┬  ┌──┐ ← 顶部压舌：盖住 PCB 上缘 0.9mm，锁 +Z
z = pcb_z1 + 0.4      ┤  └──┘   （0.4mm 就是板卡能上抬的**全部**行程）
z = pcb_z1 (50.9)     ┬  ┌──┐ ← 卡钩：顶住 PCB 后表面，过盈 1.5mm，锁 +Y（抗 pitch）
z = 48.9              ┤  └──┘
                      │  │  │ ← 悬臂 17 × 1.6，朝 ±X 弹
z = 33.9              ┴  └──┘ ← 根部，接在下段刚性导轨上
```

三个设计决定，每个都有非它不可的理由：

| 决定 | 为什么 |
|---|---|
| 悬臂沿**全局 Z** 生长 | 推荐打印姿态（+Y 朝上）下这是**水平**方向，弯曲应力在层内。沿 Y 生长的话正好是层间受拉 —— 塑料件最容易断的方向 |
| 变形方向 **±X** | 必须垂直于板卡的插入方向 −Y。平行的话怎么让都让不开（板卡扫过的正是那个方向） |
| 卡钩落在 **z 48.9~50.9** | 把板卡背面按 2mm 网格扫了一遍，**完全没有元件**的只有两段：下缘 10.9~14.9（压唇已占）和上缘 48.9~50.9。排针背高 8.4mm、外缘到 \|x\|=12.6，钩子伸到 12.0 时如果 Z 上和排针重叠就会顶在排针塑料座上（只差 0.6mm）。**"背面还有空地吗"这种问题必须去量，不能猜** |

钩（过盈 1.5）和压舌（过盈 0.9）共用同一根悬臂：让开的量由**大的那个**决定，
小的那个必须在整个推入过程中都被带着让开，所以它的斜面更靠前、过盈更小。

装配动作没变，但现在有**三声咔**：推到底两声（两侧卡钩越过 PCB 后缘），
落下再一声（压舌扣住上缘）。三声都听到才算装好。
拆板：从后开口伸进一字小螺丝刀把两侧悬臂各撬开 1.5mm。

#### 三条新判据（以及为什么老判据抓不住这个问题）

| 判据 | 内容 | 老判据为什么漏了 |
|---|---|---|
| `CONS-16` | **扫角度**找板卡能 pitch 到几度（要求 ≤2°） | 老判据只做**平移**试探。+Y 平移被压唇挡住 → `CONS-14` 通过；但板卡可以绕压唇**转**出去。**平移试探测不出转动自由度。** |
| `CONS-17` | 上抬 4mm 必须被压舌挡住 | 老判据里 +Z 根本没有对应条目（因为约束是"重力"） |
| `CONS-18` | 悬臂应变 ε = 3tδ/(2L²) ≤ 1.6%；侧壁让位空间 ≥ 过盈 + 0.3；根部以上不许被导轨背住 | 老设计没有弹性件 |

`CONS-16` 一开始写成"固定角度下的干涉体积"，踩了两个坑，都实际发生过：

* 3° 时干涉只有 4.4mm³，和布尔容差 2.0 差不到一个量级，判据很脆；
* **角度取大反而更小**（5° 只有 1.8mm³）—— 板卡上缘已经整个转到卡钩**后面**去了。
  **"推得越狠干涉越大"这个直觉对有限尺寸的挡块不成立。**

改成扫角度找"第一个被挡住的角度"之后，读数本身就有物理意义：
**板卡在腔里能晃 2.0°，上缘摆幅约 1.4mm。**

> **把新判据在旧几何上跑一遍，确认它真的会红。** 这一步做了：
> 注释掉卡钩之后 `CONS-16` 报"扫到 4° 仍无干涉 —— 这个方向**没有约束**"、
> `CONS-17` 报 0 干涉，而 `CONS-14`（老判据）**依然通过** ——
> 和实物表现完全一致。**没红过的检查不能算数。**

**止挡面为什么落在下缘带而不是四周一圈**：前侧贴片元件一直铺到 X ±12.81，
而 PCB 只有 ±13.5，两侧根本剩不下台阶；只有 Z < 19.36 那一段前侧完全干净
（27 × 8mm），足够做止挡。这条结论同样是从 STEP 里一格一格量出来的。

EVA 泡棉现在退化成**减振垫**，不再承担定位职责。
镜头位置仍然由摄像头模组在方腔里的落位决定，而不是由 PCB 决定 ——
光学重复精度不受影响。

> 也考虑过"顶部竖直滑入 + 两侧全高 C 型槽"——Y 向锁得最死，但要在吊舱顶开一条
> 32×8mm 的长槽，楼梯间的灰和冷凝水会直接进电子舱；而且吊舱顶到天花板只有
> 12mm，40mm 高的板根本举不起来。代价大于收益，几何上也不成立。

### 5.8 走线

全部内藏，外表面无可见线缆：

```
LED 座孔 → 引线过孔 → 立板内侧竖槽 → 横槽 → 吊臂 U 型腔 → 吊舱电子舱
5V 电源 → 吊舱底面水滴孔（朝下，防结露倒灌）
```

吊臂做成**下开口 U 型槽**（壁厚 2.5mm），线走在腔内，从下方才看得见。
同时满足三件事：走线路径、DfAM"禁止实心大块"、比刚度高于实心杆。

自检 `WIRE-02` 把整条路径上的空腔并起来查连通域数 —— 这是把 `TOPO-01`
的思路用在"洞"上：**每一段都挖了 ≠ 它们连成一条**。

### 5.9 DfAM 落实（对齐 `dfam_rules.md`）

| 准则 | 落实 |
|---|---|
| 悬垂 ≥45° | 撑座 loft 约 64°、托台斜撑、吊臂顶壁 ≤4mm 桥接 |
| 水平孔水滴形 | `geometry.teardrop_z`，用于底部进线孔 |
| 功能特征代支撑 | 撑座本身即加强结构 |
| 禁止实心块 | 吊舱抽壳 2.5mm、吊臂 U 型、立板 7mm 板状 |
| 圆角过渡 | 外轮廓 R3、吊舱边 R3、其余 R1.2~2 |
| 运动/静态间隙 | 滑盖舌槽 0.25、定位销 0.2、PCB 0.3~0.4 |
| 各向异性 | 立板为板状件，主拉应力在层内 |
| 非流形 | 全局 `EPS=0.01`，所有减法体加微元 |

**推荐打印姿态**（`checks/dfam.py: PRINT_ORIENTATION`，悬垂统计就按它算）：

| 件 | 姿态 | 理由 |
|---|---|---|
| `body` | 绕 X 轴 **+90°**（+Y 朝上） | 吊舱腔口朝上零支撑；镜头孔变竖直孔；立板层向平行于弯曲中性面 |
| `mirror_holder` | 绕 X 轴 **+135°** | 45° 反射面朝正上，T 型槽朝上零支撑 |
| `slide_cover` | 绕 X 轴 **+90°** | 平放 |

## 6. 防呆设计

防呆分三层，**只有第一层能被机器验证**：

| 层次 | 说明 | 本设计里的实例 | 可验证 |
|---|---|---|---|
| **几何** | 装反就是装不进去 | LED 极性切边、滑盖定位筋、前腔 Z 不对称 | ✅ `POKA-02/03/04/05` |
| **导向** | 装错会明显别扭 | 方腔入口倒角、PCB 侧导轨、托板落座感 | 只能人工体会 |
| **标识** | 刻字提醒 | 托板横梁 `COATED SIDE DOWN` | ℹ️ `POKA-06` 仅记录 |

### 6.1 LED 极性（最硬的一处）

真实草帽灯法兰上有一条切边标记阴极（`led.step` 实测：法兰 Ø5.8，切边距轴心 2.4）。
座孔做了同样的切边（Ø6.0，切边距轴心 2.5）。

装反时法兰被挡 `2.90 − 2.50 = 0.40mm` —— 不靠标识、不靠说明书，**靠形状**。

> **判据要用线性量，不能用体积。** 法兰只有 1mm 厚，转 180° 后的干涉体积
> 不到 1mm³，和布尔噪声容差（2mm³）分不开。这个坑值得记一笔：
> **反向判据的阈值必须比正向判据的容差高一个量级，否则那条检查是假的。**

### 6.2 滑盖定位筋

+X 滑槽底部有一条 10mm 长的筋，盖板 +X 舌片的**最下面一段**相应收窄。

* 正装 → 筋落进收窄段，无阻碍；
* 上下颠倒 → 收窄段跑到顶部且换到 −X 侧 → 满宽舌片撞上筋；
* 前后调头 → 收窄段换到 −X 侧 → 同样撞。

**筋必须紧贴槽底。** 放在中段会把正装也一起挡住 —— 盖板从上往下滑，
舌片的满宽部分下滑时一定会先经过中段的筋。
（这个错误第一版就犯了，`SEQ-01` 装配第 9 步立刻报了出来。）

### 6.3 开发板方向

前腔在 Z 方向**不对称**（SD 卡座偏上、排线尾端偏下），
板子上下颠倒或前后调头都会顶到台阶。
如果哪天让位槽被改成上下对称，`POKA-04` 会立刻报错 —— 那正是它的用处。

### 6.4 镜片朝向：诚实地标为"做不到"

前表面镜必须镀膜面朝下。但它是**一块两面一样的矩形玻璃，做不成几何防呆**。
所以：

* 托板横梁上刻 `COATED SIDE DOWN`；
* `ASSEMBLY.md` 第 11 步有对应的检查动作；
* 识别方法：**用笔尖轻触镜面，笔尖和倒影没有间隙的那面才是镀膜面。**

把这一条标成 `INFO` 而不是假装解决了 —— 假的安全感比已知的风险更危险。

## 8. 代码结构

```
params.py     纯数字（实测/采购/设计/估算），**唯一允许出现尺寸的地方**
    ↓
layout.py     尺寸链：参数 → 位置与基准面。判据式子写在注释里
    ↓
geometry.py   建模原语：按起止坐标建体、mirror_x、水滴孔、带切边的圆柱
    ↓
parts/*.py    三个打印件      refs.py  参考件（按可信度分级）
    ↓
model.py      Design：一次配置的全部实体，带缓存
    ↓
checks/*.py   自检     optics.py 光路仿真     export.py 导出     report.py 报告
```

**依赖方向严格自上而下，不许反向。**

三条编码规矩（违反了很难被发现，所以写死在这里）：

1. **建模函数里不许写魔法数字。** 要新尺寸就去 `params.py` 加字段。
2. **左右对称一律用 `geometry.mirror_x`**，不许写 `for s in (-1, 1)`。
   `cube` 只向 +X 生长，`s*X` 乘号会让 −X 侧的槽跑到对侧表面
   （DESIGN_NOTES §7.2）。用镜像算子让"左右不对称"在语法上不可能。
3. **实体一律用起止坐标定义**（`bx(x0,x1,y0,y1,z0,z1)`），不用"中心+尺寸"。

`parts/body.py` 还有一条结构性规矩：**先加料、再一次性去料、最后长内部特征**。
吊臂在吊舱端会伸进主型腔，若先挖腔再并吊臂，腔里会留下一坨实心料，
正好挡在板卡旁边 —— 这种错误在渲染图上几乎看不见。

## 9. 自检套件

140 条规则，10 个分类。设计哲学三条：

### 9.1 拓扑检查是性价比最高的

```python
len(part.solids()) == 1
```

一行代码消灭了折磨了十几个版本的整个错误类别（零件悬空）。
CAD 的 union 对不相接的实体一样能编译通过，**没有任何警告**。

### 9.2 不只查"不干涉"，还要证明"约束成立"

`A ∩ B = 0` 只说明装得进去，不说明装上后不会掉。每个约束都配**反向测试**：

| 正向 | 反向 |
|---|---|
| 主体 ∩ 托板 = 0 | 托板下沉 0.5mm **应当**干涉 |
| 主体 ∩ 滑盖 = 0 | 滑盖前后各推 0.6mm **应当**干涉 |
| 托板 ∩ 镜片 = 0 | 镜片外推 1.2mm **应当**干涉 |
| 主体 ∩ 板卡 = 0 | 板卡前推/侧推/下沉 **应当**干涉 |

§7.5 的"托台顶死托板"，**只有反向测试能自动抓住**。

### 9.3 把空间想象题变成可计算判据

* **光路**：做成实体（体积粗筛）+ 逐点射线追踪（精确定位）；
* **装配顺序**：写成 `assembly.py` 的路径数据，沿路径逐点做布尔；
* **走线**：把路径上的空腔并起来查连通域；
* **净空**：三角化成点云，逐点核算"表盘正上方区域"内的最高点。

### 9.4 分类

| 分类 | 管什么 | 典型规则 |
|---|---|---|
| `TOPO` | 拓扑 | 单一连通实体、is_valid、体积量级 |
| `FIT` | 装得进去吗 | 件间干涉、板卡包络、模组在方腔里、泡棉够不够厚 |
| `CONS` | 装上会不会掉 | **全部是反向测试** |
| `SEQ` | 按这个顺序装得起来吗 | 沿路径碰撞 + 全程净空 |
| `OPT` | 相机看得见吗 | 逐点光线追踪、有效口径、字符像素、景深、渐晕 |
| `LED` | 会不会有高光/阴影 | 掠射高度、入射角、反射瓣偏离量 |
| `DIM` | 尺寸链 | 抱箍过盈、夹持带位置、天花板、打印空间 |
| `DFAM` | 打得出来吗 | 悬垂面积占比、壁厚采样 |
| `POKA` | 装反了会怎样 | **全部是反向判据：必须装不进去** |
| `WIRE` | 线走得通吗 | 空腔连通域 |

#### 判据设计的六条经验（都是被具体错误换出来的）

1. **遮挡判据的可信度上限 = 它的遮挡物清单的完整度。**
   漏过两次，两次都是漏了一个真实存在的东西（先是 `mirror_holder`，
   后是水表**自己**的蓝环和蓝盖）。
   文档里写着"本条逐点验证"不等于它真的在验 —— 清单要和文档对得上。
2. **平移试探测不出转动自由度。** 板卡的 +Y 平移被压唇挡住（`CONS-14` 通过），
   但它可以绕压唇**转**出去。失效动作是什么，判据就该做什么动作。
3. **"推得越狠干涉越大"对有限尺寸的挡块不成立。**
   `CONS-16` 用 5° 试探反而比 3° 干涉更小 —— 板卡上缘已经转到卡钩后面去了。
   改成"扫角度找第一个被挡住的角度"，读数还有物理意义。
4. **反向判据要挑一个只有被测特征能到达的区域。**
   `DIM-13`（座圈）把判定区间限制在 z ∈ [银圈顶−0.6, 银圈顶]，
   内棱（顶 z=+2.0）够不到那里，读数才干净。`CONS-15` 同理。
5. **一条永远满足不了的判据比没有判据更糟。**
   补全遮挡物之后 `LED-05` 的"每点两灯可达"在物理上不可能成立；
   正确做法是拆成"任何点不许全黑"（硬）+ "OCR 区两灯可达"（警告），
   而不是放宽阈值蒙混过去 —— 后者会训练出"忽略红字"的习惯。

6. **"标称间隙"和"真实间隙"往往不是同一个量。**
   `holder_cover_clear = 0.8` 加在托板的切面上，而真正离蓝盖最近的是**玻璃的
   后-背角**，真实间隙只有 0.39mm（`FIT-15`）。参数名要说清楚它是谁到谁的间隙。

外加一条关于**阈值**的：靠调高阈值来容忍已知噪声，等于把检查的分辨率一起调没了。
`DFAM-02` 遇到刻字（笔画 0.45mm，天生细于 `min_wall`）时，
正确做法是把刻字**填平再量**（`Design.thickness_probe_parts`），
而不是把 2% 的阈值抬到 3%。

### 9.5 加一条规则

```python
@rule("OPT-12", "OPT", "标题",
      why="这条规则存在的理由 —— 通常指向 DESIGN_NOTES 里的某个坑")
def my_check(design):
    v = inter_vol(design.body, something)
    return v < design.cfg.mfg.vol_tol, f"{v:.2f} mm³"
```

`why` 不是装饰：报告里失败项会把它一起打出来，
下一个接手的人看到 FAIL 不用猜"这条到底在防什么"。

**新增了结构就要新增对应的检查。** 这是提交的前提。

### 9.6 已知的局限

* **壁厚**和**悬垂**都是**采样**方法，不是证明。能拦住明显问题，
  不能替代切片器预览。
* **桥接跨度**没有自动检查。
* **重心 / 悬臂挠度**没有估算。
* `watermeter-dn25.step` 是 DN25，**任何判定都不许引用它**；
  判定用的是 `refs.meter_mock()`（卡尺实测参数化）。

## 10. 未验证的假设

按风险从高到低。**每一条在 `params.py` 里都标了 `[估算]`。**

| # | 假设 | 风险 | 验证方法 |
|---|---|---|---|
| 1 | 抱箍单边过盈 0.25 合适 | 太紧装不上，太松打滑 | **优先只打抱箍试配（T1）** |
| 2 | 弹性卡钩过盈 1.5mm 的手感 | 太紧装不进，太松压不住 | 试印一段侧壁 + 悬臂，拿废板卡试插（T1b） |
| 3 | **表盘的转向** | 现在按"任意转向"保守建模。知道了转向就能确认那两台被墙挡住的表**具体丢的是哪个小盘的边** | 第一台拍一张照 |
| 4 | 弧面玻璃会把反射瓣展宽多少 | 眩光判据按**平面**算得 27.9°，实际瓣更宽 | 第一台拍照看有没有亮斑；有就贴偏振片（吊舱前壁已留 Ø20 沉孔） |
| 5 | 吊舱正上方无障碍 | 滑盖抽出需 70mm 净空 | 现场目视 |
| 6 | 传感器长轴朝向 | 影响 ROI 框法（不影响能否成像） | 第一台拍一张 |

**建议验证顺序**：1 → 2 → 3/4（都在第一台实物上一次解决）。

> **从这张表里毕业的四条**（对照着看很有意思）：
>
> * `glass_depth = 7mm` → 实测推出 **4.0**。那 3mm 直接从天花板余量里扣掉，
>   还让抱箍夹持带有 2.5mm 骑在空气里。**估算值不会报错，它只会安静地吃掉余量。**
> * 蓝盖**铰链位置** → 一度以为"已知"，结果那才是真正错的地方（§5.1b）。
> * 铰链**高度** → 实测 4.7，且有交叉印证，不确定度 ±1.0 → ±0.3。
> * **指针小盘的位置和半径** → 实测 R5、盘心 r=20。上一版猜的坐标
>   不但不准，还恰好避开了最糟的方位，让眩光判据报了个假的好成绩。

> **已经从这张表里毕业的两条**（对照着看很有意思）：
>
> * 原第 1 条 `glass_depth = 7mm` —— 实测推出来是 **4.0**。
>   那 3mm 的差额直接从天花板余量里扣掉了，还让抱箍夹持带有 2.5mm
>   骑在空气里。**估算值不会报错，它只会安静地吃掉余量。**
> * 原「蓝盖停在哪」—— 实测固定环直径解决了一半，
>   但**铰链位置**当时被当成已知量，结果那才是真正错的地方（见 §5.1b）。
>   一条假设"验证过了"不等于它周围的假设也验证过了。

### 10.1 提测量要求之前，先跑灵敏度分析

上一轮让业主去量盖板的半径和厚度。**跑完扫描才发现这两个数根本不影响任何判定**
（见 §5.1b）—— 白折腾了一趟人。

这一轮的三条实测请求（指针盘位置、铰链高度、盖板停放角）都先做了扫描：
每一条都能明确说出"量准之后能换回多少余量"。

> **让人去量之前，先证明这个数值得量。**
> 扫一遍参数只要几分钟，而爬楼梯拿卡尺的是人。

## 11. 换开发板 / 换表型

### 11.1 换开发板（适配 `esp32s3cam-1` / `-3`）

```bash
python build.py inspect esp32s3cam-1.step     # 量出包络与子件清单
# 把数字填进 params.BOARDS 里的一条新 BoardSpec
python build.py check --board esp32s3cam-1
```

要量的（对应 `BoardSpec` 的字段）：

1. PCB 的三向范围、板厚；
2. 光轴位置（摄像头模组本体的中心），**注意哪一侧朝上**；
3. 镜头前端面、模组本体前/后端面、镜筒直径；
4. 前侧深级/浅级元件的包络（决定两级让位槽）；
5. 背面最高元件的伸出量。

`FIT-05` 会拿真实 STEP 反过来核对包围盒，抄错会立刻报错。

### 11.2 换表型

只改 `params.Meter` 一段。其余尺寸链会自动跟随，并被 `DIM-01~04` 拦一遍。
但要先确认两件事：

1. **表盘姿态**是不是朝上（不是的话整个架构都要重来）；
2. 银圈外径、可视表盘直径、上方净空，这三个是全部设计的基准。

## 12. 协作规矩

### 12.1 提交前

```bash
python build.py check          # 阻断性失败必须为 0
```

有新增结构就要有新增自检项。`out/report.md` 一起提交，方便做版本间 diff。

### 12.2 给下一个 AI 的九条

1. **先读 [DESIGN_NOTES.md §7](DESIGN_NOTES.md)，再动手。** 那些错误机制会重演。
2. **不要相信自己的空间想象。** 把每个几何判断写成可计算的判据放进自检。
   十三个版本的统计事实：可手算复核的东西出错率低且能自我发现；
   需要空间想象的东西出错率高且**不能**自我发现。
3. **看不到渲染结果就明说。** 本项目所有结构性错误都是人发现的。
4. **收到推翻自己判断的数据时，先追问测量语义**，不要直接采信
   （§7.4：一个"300mm"让整版设计报废）。
5. **给出的判据式子要写出来。** "我算过了"不是证据。
6. **做减法。** 每加一个结构，问"没有它会怎样"。
7. **新写的判据必须在旧几何上红过一次。**
   把被修的那个特征注释掉再跑一遍 —— 没红过的检查不能算数。
   这一版靠它发现 `DIM-13` 的探针方向写反了（永远量到 0，永远"通过"）。
8. **扫描能证伪的只有它扫过的维度。**
   上一轮扫了盖板的半径和厚度，结论"不敏感"至今成立；
   但真正敏感的**铰链位置**当时被当成已知量，压根没进扫描 —— 于是错的正是它。
   报告扫描结论时，把**没扫的维度**也列出来。
9. **提测量要求之前，先证明那个数值得量。**
   扫一遍参数几分钟，爬楼梯拿卡尺的是人。
   每条测量请求都要能回答"量准了能换回多少余量"。

### 12.3 三条容易踩的工具坑（都是这一版踩出来的）

* **`import_step` 返回的嵌套 Compound 直接做布尔会静默返回空集**，
  所有干涉检查一起"通过" —— 最危险的假阴性。
  凡是要参与布尔的 STEP，必须走 `refs.load_step_fused()`。
  发现它的线索是：三条互相独立的检查同时报出同一个可疑的 0。
* **反向判据的阈值要比正向容差高一个量级**，否则那条检查是假的（§6.1）。
* **`Axis` 求交返回的是整条直线的交点，包含反向**，必须自己按参数 t 过滤，
  否则相机后方的结构件会被误判成遮挡物。
