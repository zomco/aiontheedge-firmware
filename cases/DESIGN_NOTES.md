## 1. 项目背景与约束

### 1.1 目标

在**不更换既有水表**的前提下，给自建出租房的 **40 块机械水表**加装光学抄表装置，
读数回传 Home Assistant，减轻房东抄表负担并支撑智能化场景（漏水报警等）。

### 1.2 硬约束

| 约束 | 值 | 来源 |
|---|---|---|
| 不能更换水表 | — | 业主要求 |
| 表盘上方净空 | **70mm**（40 台最小值，自银圈顶面起算） | 实测 |
| 单机 BOM | 目标 ≤ 50 元 | 业主预算 |
| 必须保留人工抄表 | 每月 1 日 + 租户争议时 | 业主要求 |
| 固件开源 | AI-on-the-edge 或其衍生 | 业主要求 |
| 端侧完成识别 | 只回传读数 | 业主要求 |

### 1.3 现场条件

- 楼梯半层，每层 6 块表垂直排列，共约 7 处
- 表前方净空 **1 米以上**，住户日常走电梯，几乎无人经过
- 每层一路 5V/10A 开关电源，到表约 2m，旁边就是 WiFi 热点
- 局域网已有约 100 个物联设备 + 24 路 NVR
- 冷水，PPR 管，楼梯间潮湿（结露风险）

### 1.4 水表

宁波埃美柯 **LXSY-15E2**，旋翼式液封冷水表，DN15，G3/4B 接口，L=165mm，Q3=2.5 m³/h。
表盘朝上（与地面平行），5 位字轮 + 4 个指针（×0.1 / ×0.01 / ×0.001 / ×0.0001 m³）。

## 2. 坐标系与命名约定

**这一节是所有几何讨论的前提，任何时候不要改动。**

```
原点 O  = 水表表盘玻璃面的中心
+X      = 沿水表体轴线（左右方向），模型左右对称
+Y      = 离墙方向（房间一侧）；吊舱、滑盖抽出、整机拆卸都在这一侧
+Z      = 垂直向上；上方净空 70mm 是全项目最紧的约束
```

关键平面高度：

| 特征 | Z |
|---|---|
| 表盘玻璃面 | 0 |
| 银圈顶面 | +7 |
| 银圈底面 | −14.1 |
| 银圈底部凸台顶 | −11.3 |
| 天花板（障碍物） | **+77** |
| 镜面中心 = 镜头光轴 | +42 |

**约定：任何新写的模块，注释里必须写清坐标变换映射**，格式：

```
# 变换映射: 局部(a,b,c) -> 全局(c, a, b)
```

理由见 §7.1。

## 4. 光学设计

### 4.1 核心难题与解法

表盘朝上，上方只有 70mm 净空，而相机需要 100mm 以上的工作距离才有可用景深。

**解法：45° 前表面反射镜折叠光路。**

```
表盘 ──垂直上行 42mm──> 45°反射镜 ──水平前行 80mm──> 镜头
```

- 总光程 **122 mm**，但竖直方向只占用 **约 60 mm**
- 相机与电子件全部移到 +Y 方向（有 1 米净空），完全不占稀缺的竖直空间

### 4.2 光学参数

| 量 | 值 | 说明 |
|---|---|---|
| 成像半径 ROI_R | 29 mm | 覆盖 Ø56.5 表盘 + 余量 |
| 镜面/光轴高度 | 42 mm | |
| 镜头前端面 Y | 80 mm | |
| 总光程 | 122 mm | |
| 光锥在镜面处半径 | 19.02 mm | |
| 45° 面与光锥交线（椭圆） | Y ∈ [−24.95, +15.36] | |
| **镜片实需** | 57 × 38 mm | |
| **采购镜片** | **70 × 50 × 2 mm** | 余量 13 / 12 mm |
| 单字符成像 | **44.4 px** | AI-on-the-edge 需 ≥20px |
| 景深容差 | ±11 mm（f/2.4，CoC=4.4µm） | |

### 4.3 反射镜采购规格（重要）

| 项 | 要求 |
|---|---|
| 类型 | **前表面反射镜（第一表面镜）** |
| 尺寸 | 70 × 50 × 2 mm |
| 镀层 | 铝 + SiO₂ 保护膜 |
| 反射率 | 可见光 ≥ 88% |
| 平面度 | 普通商用级即可 |

**必须是前表面镜。** 普通背镀镜玻璃前后两次反射产生双像鬼影，字轮出现重影，
OCR 直接失效。镀膜面不可擦拭（只能气吹），划伤即报废，**建议多买 2 片备用**。

> 曾经建议过「用报废机械硬盘盘片替代」——**在这个尺寸下不成立**：
> 3.5" 盘片外径 95mm、中心孔 25mm，可用环带只有 35mm 宽，放不下 70×50，
> 而且中心孔会落在光路上。

### 4.4 眩光抑制

表盘是「Ø56.5、深 7mm 的井」，上面盖着弧面玻璃 + 液封介质。
**同轴照明（板载闪光灯）必然在字轮上打出镜面高光——这是几何问题，调亮度无效。**

解法是离轴：**两颗 LED 置于 (±38, 0, 30)**，射向表盘中心。

| 检查 | 数值 |
|---|---|
| 光线在银圈内缘（r=28.25）的高度 | 21.9 mm > 7 ✓ |
| 单侧覆盖范围 | ρ 从 −28.25 到 +25.3 |
| 最小入射角 | 22.9°（采集锥半角仅 13.4°）✓ |
| 镜面反射瓣 | 全部打偏，不进采集锥 |

**必须是对置两颗，不是冗余而是几何必需**：单颗 LED 在 60° 入射角下，
井壁会在对侧投出约 12mm 宽的阴影带，正好压住最外圈指针。两颗互补。

**LED 型号**：5mm 草帽型白光，发光角 **120°**。
覆盖 Ø56.5 需要 58.4° 全角，普通 5mm 圆头只有 15~30°，会打出中心亮斑、四个指针全黑。

**偏振片**：吊舱前壁留了 Ø20 × 1.2 沉孔作为对冲。手电筒实验显示字轮无高光，
所以默认不装；若现场发现残余眩光，贴一片 Ø20 线偏振片 + LED 前贴一片旋 90° 即可。

## 5. 机械设计

### 5.1 三个打印件

| 件 | 体积 | 作用 |
|---|---|---|
| `body` | 116.4 cm³ | 抱箍 + 撑座 + 立板 + LED座 + 镜托台 + 吊臂 + 吊舱（**单一连通实体**） |
| `mirror_holder` | 20.6 cm³ | 45° 托板 + 三角耳 + 支承脚（**每月抄表时整块提起**） |
| `slide_cover` | 7.7 cm³ | 竖直下滑，无螺丝 |

### 5.2 抱箍：为什么这样设计

**曾经的致命错误**（见 §7.3）：内孔比银圈大 2.4mm，剖分缝只有 2.2mm，
完全闭合仅缩小 0.70mm，**永远碰不到银圈**。

现在的方案：

| 项 | 值 | 理由 |
|---|---|---|
| 光孔 | Ø82.8（单边 +0.35） | 便于套入 |
| **16 条内棱** | 内切 Ø81.6（**单边过盈 0.25mm**） | 只有棱接触，局部压强高十几倍，抗转 |
| 剖分缝 | 4 mm | 留弹性张开行程 |
| 夹持带 | Z −10 ~ +6.5（16.5mm） | 避开底部凸台顶（−11.3），低于银圈顶（7） |
| 夹紧螺栓 | 两颗 M4，z = −6 / +2.5 | 上下受力均匀，防止带子张成 V 形 |
| 备用 | 前侧对称两个 Ø3.2 径向孔 | 棱纹不够时可拧 M4 自攻顶紧 |

**内棱的坑**：16 条棱里若有一条落在剖分缝内，会被切成孤立薄片。
代码里已加过滤（自检 `solids==1` 会报）。

**关于「校准固化」**：银圈顶部凹台位置逐台不同，说明表头装配角度本身随机，
所以**支架绝对朝向无法也不需要统一**——每台 ROI 本来就要在软件里各框一次。
需要保证的只是**同一台反复拆装后角度可复现**：靠抱箍不打滑 + 托板四点销定位。

### 5.3 镜片托板：四点支承 + 垂直提起

每月人工抄表时，镜片挡住字轮，必须移开。
方案是**只取下 30g 的托板**，而不是移动 100g 的整个悬臂。

- 托板通过两片三角耳落在立板的**水平托台**上
- 4 根 Ø4 竖直定位销约束（间隙 0.2mm，竖直销零支撑打印）
- **垂直上提 6mm 即脱离**，读完放回

**关键约束（曾经出错，见 §7.5）**：
托台顶面是**水平**的，托板底面是 **45° 斜面** `z = y + 42`。
**托台顶面必须低于该段托板底面的最低点**，否则一端顶死一端悬空。

| 托台 | Y 范围 | 该段托板底面最低 | 托台顶面 |
|---|---|---|---|
| 后 PAD1 | −20 ~ −12 | 22 | **20** |
| 前 PAD2 | +10 ~ +18 | 52 | **50** |

**另一个约束**：支承脚必须止于立板内侧面（X=42.5）之前 → 脚外缘 **X=42**。
托台是主体的一部分，可以伸进立板；脚不行。

### 5.4 镜片 T 型槽

反射面朝下，直通方槽会让镜片掉出来。改成 T 型槽：

- 深部 50.2mm 宽容纳镜片
- 开口收窄到 45.6mm，**两侧各留 2.2mm 唇口**
- 从一端沿局部 −Y 滑入（全局方向为斜向上前方，行程约 80mm）

**镜片是在台面上装进托板的，不是在现场装。** 现场只做「整块托板提起/放回」。

### 5.5 滑盖：真正的 C 型槽

**曾经的错误**（见 §7.6）：槽只约束 X，盖板可以直接向后掉出来。

现在的结构（沿 Y 从前到后）：

```
Y 88 ~ 108.8   侧壁前沿      → 约束 -Y
Y 108.8~112.2  滑槽(X±19.5)  → 盖板舌片(X±19.3)在此，约束 X
Y 112.2~114    后压边(1.8mm) → 约束 +Y
```

盖板从顶部插入，竖直下滑，底部限位。间隙 0.2mm。顶部有手指凹槽。

### 5.6 吊舱：阶梯型腔固定板卡

不用任何额外零件固定 ESP32-S3-CAM：

| 约束 | 实现 |
|---|---|
| **Y（前后）** | 型腔前段只有 28mm 高（容纳 27mm 模组），板是 40mm 高，**进不去** → 台阶天然成为前止挡 |
| **X（左右）** | 前段宽 27.8mm，模组被两侧内壁夹住 |
| **Z（上下）** | 前壁台阶挑出的 2mm 承台，板下缘落在 z=11 |
| **压紧** | 滑盖内侧贴 3mm EVA 泡棉，把板顶向前止挡 |

用泡棉而非硬定位，是因为板背面元件高度存在公差。
**副作用是好的：镜头位置由摄像头模组决定，而不是由板决定，光学更准。**

### 5.7 走线

全部内藏，外表面无可见线缆：

```
LED卡槽 → 立板内侧竖槽 → 立板内侧横槽 → 吊臂U型腔 → 吊舱电子舱
5V电源 → 吊舱底面水滴孔
```

吊臂做成**下开口 U 型槽**（壁厚 2.5mm），线走在腔内，从下方才看得见。
同时满足三件事：走线路径、DfAM「禁止实心大块」、比刚度高于实心杆。

### 5.8 DfAM 落实

| 准则 | 落实 |
|---|---|
| 悬垂 ≥45° | 撑座 64°、托台斜撑 55°、吊臂顶壁 4mm 桥接 |
| 水平孔水滴形 | `make_teardrop_z()`，用于底部进线孔 |
| 功能特征代支撑 | 撑座本身即加强结构 |
| 禁止实心块 | 吊舱抽壳 2.5mm、吊臂 U 型、立板 7mm 板状 |
| 圆角过渡 | 立板轮廓 R3、吊舱边 R3、其余 R1.2~2 |
| 运动/静态间隙 | 滑盖舌槽 0.2、定位销 0.2 |
| 各向异性 | 立板为板状件，主拉应力在层内 |
| 非流形 | 全局 `EPS=0.01`，所有减法体加微元 |

**推荐摆放**：主体绕 X 轴 −90°（+Y 朝上）→ 吊舱腔口朝上零支撑，
镜头孔变竖直孔，立板层向平行于弯曲中性面。托板平放镜面槽朝上。滑盖平放。

## 6. 电气设计

### 6.1 LED 驱动：为什么必须要 MOSFET

白光 LED 的 **Vf ≈ 3.0~3.2V**，而 ESP32-S3 的 GPIO 高电平只有 3.3V。
**压差仅 0.1~0.3V，限流电阻无法工作。** 必须从 5V 供电，GPIO 只控制栅极。

| 元件 | 规格 | 数量 |
|---|---|---|
| N-MOSFET | AO3400A（SOT-23） | 1 |
| 限流电阻 | 100Ω 0.25W | 2 |
| 栅极下拉 | 100kΩ | 1 |

I = (5 − 3.1)/100 ≈ 19 mA/颗，双颗共 38mA 全走 MOSFET。
**不要直接用 GPIO 灌 40mA**，ESP32-S3 单脚安全值是 20mA。

四个元件焊在 15×20mm 洞洞板上，装在吊舱下部电子舱（不在 LED 处），
这样通往 LED 的只有两根简单导线，发热和电子件远离光学部分。

### 6.2 供电与网络

- 每层 5V/10A 开关电源带 6 台（峰值 6×0.6A ≈ 3.6A，余量充足）
- **主干线必须 ≥0.75mm²**：0.3mm² 在 3.6A 下压降 0.4V+，ESP32-S3 发射瞬间会棕出
- 每台本地并 **470–1000µF + 100nF**
- 开关电源装阻燃盒、加保险丝（旁边就是灭火筒，不是可以省的地方）
- **结露防护**：吊舱进线孔朝下，防止冷凝水沿线倒灌

**网络风险（尚未解决）**：24 路 NVR 若有任何一路走 WiFi，2.4GHz 已被占满。
建议给抄表设备单独 AP/SSID，固件加 0~900s 随机延迟启动避免关联风暴。

### 6.3 固件路线

- **AI-on-the-edge**（slider0007 的 ESP32-S3 fork）
- **SD 卡消除**：改分区表，用 `esp_vfs_fat_spiflash_mount_rw_wl()` 替换
  `esp_vfs_fat_sdmmc_mount()`，**挂载点保持 `/sdcard` 不变**（代码里遍布硬编码路径）
- 必须关掉图像和日志落盘（NOR Flash 扇区寿命约 10 万次）
- **⚠ 分区表变更后 OTA 无法从有卡版升级，40 台必须逐台接 USB 重刷**，
  所以分区布局必须在批量部署前定型

**⚠ 许可证风险**：slider0007 公开声明该 fork「仅供非商业用途」。
若目标是商业化，必须核实两个仓库的 LICENSE 并直接联系作者。
即使重写固件，仍会用到 jomjol 训练的 `dig-class100` / `ana-class100` 权重——
**建议用自有 40 块表积累的图像重新训练**，顺带解决权利问题。

## 7. 踩过的坑

**这是本文档最有价值的部分。**
记录的不是「哪个数错了」，而是**产生错误的机制**。

### 7.1 坐标变换复合：`rotate` 的映射从不逆向验算

**症状**：整个立板飞到别处，挂在它上面的 LED 座、托台、吊臂、走线槽全部悬空。

**原因**：
```openscad
rotate([0,90,0])   // 映射: (a,b,c) -> (c, b, -a)   轮廓两轴互换 + 整体外移
rotate([90,0,0]) rotate([0,90,0])   // 正解: (a,b,c) -> (c, a, b)
```

**教训**：**凡是涉及旋转的模块，必须在注释里写出完整映射并逆向代入验算。**
build123d 版里用 `Plane.YZ * sketch` 替代手写旋转，从语法上消除了这类错误。

### 7.2 `s*X` 乘号 + 单向生长的 `cube`

**症状**：走线槽一边在外表面、一边在内表面；夹紧耳不对称。

**原因**：
```openscad
translate([s*(MAST_X + MAST_T/2 - WIRE_D), ...]) cube([WIRE_D, ...])
// cube 永远向 +X 生长；s=-1 时槽跑到了对侧表面
```

**教训**：**不要用 `for(s=[-1,1])` 做镜像**，用真正的镜像算子：
```openscad
module sym() { children(); mirror([1,0,0]) children(); }
```
```python
def mirror_x(part): return part + mirror(part, Plane.YZ)
```
**左右不对称在语法上变得不可能**，而不是靠人工记得写对符号。

### 7.3 尺寸链不闭合：抱箍在几何上不可能夹紧

**症状**：实物打印后，抱箍拧到底仍可绕表盘轻松转动。

**原因**：
```
R_IN = 41.05(银圈半径) + 1.2(TPU衬垫) = 42.25  →  内孔 Ø84.5
银圈                                          →  Ø82.1
直径间隙 2.4mm；而剖分缝只有 2.2mm
缝完全闭合 → 内孔仅缩小 2.2/π = 0.70mm  ≪  2.4mm
```

根源是**假设了一个从未列入必需件清单的 1.2mm TPU 衬垫**。

**教训**：
1. **配合尺寸必须算完整条链并写进自检**（现在有 `抱箍内棱对银圈有过盈` 一项）
2. **任何被假设存在的外购件，必须立刻写进 BOM**，否则它会在设计里"隐形存在"

### 7.4 轻信单个测量数字而不追问语义

**症状**：v0.3 整版报废。

**过程**：
- 我最初判断「进水侧裸露直管可能只有 30–40mm」（置信度 60%）
- 业主回报「300mm」，我据此**收回了反对意见**，整版围绕抱管设计
- 后续特写照片显示：**阀门到表盘边缘总共只有 132mm**，里面还塞了 5 段不同直径的东西，
  最长可抱圆柱只有 30mm，而且是最不该受力的 PPR–铜过渡件

**教训**：**收到一个推翻自己判断的数字时，要追问它的测量语义**
（"这 300mm 是否与表体同轴的裸管？"），而不是直接采信。

### 7.5 水平面与斜面的相容性

**症状**：实物打印后，镜片托板装不到位——托台一端顶死 4mm，另一端悬空 4mm。

**原因**：托台顶面是**水平**的（固定 z=26），托板底面是 **45° 斜面**（`z = y + 42`）。
在托台的 Y 范围内，托板底面从 22 升到 30，**只有正中一条线接触**。

**教训**：**斜面上的支承点，其支承面高度必须逐点核算**，不能取中值。
现在有自检项 `后/前托台顶低于该段托板底面`。

### 7.6 「有舌片」不等于「有槽」

**症状**：滑盖插进去后可以直接向后掉出来。

**原因**：挖除区贯穿了 X 全宽，把本该留作槽背衬的侧壁也挖掉了。
盖板在 Y 方向前后两侧都没有材料——舌片有了，槽没有。

**教训**：**约束必须逐自由度核算**。现在有两条对称的**反向测试**：
```
滑盖被前沿挡住（-Y 受限）   下沉/前推应产生干涉
滑盖被后压边挡住（+Y 受限）  后推应产生干涉
```

### 7.7 用错误的手算给出「已验证」的结论

**症状**：曾断言「LED 在 R=38 会被银圈挡住」，并据此把 LED 移到 R=50，
推翻了一个本来正确的方案。

**原因**：用了错误的式子 `20 × (38−30.9)/38 = 3.7mm`。
正确式子是 `z(x) = Z·(x−ρ)/(R−ρ)`，代入得 14.9mm，**根本没被挡**。

**教训**：**"我算过了"不是证据。** 判据式子本身也要写出来接受检查。
这类错误在本项目里出现过至少两次。

### 7.8 从不做连通性检查

**症状**：v0.5–v1.0 连续多版出现「零件全部悬空」，每次都靠业主渲染才发现。

**根因**：OpenSCAD 的 `union()` 对不相接的实体一样能编译通过，没有任何警告。

**教训**：这是**唯一一个可以完全自动化消灭的错误类别**。
build123d 版的第一条自检就是：
```python
ck.add(f"{nm} 是单一连通实体", len(p.solids()) == 1, f"solids={ns}")
```
**这条检查在首次运行时立刻抓到了 6 个孤立实体**（4 根定位销 + 1 条落在剖分缝里的内棱）。

### 7.9 能力边界的自我认知

十三个版本下来的统计事实：

| 类别 | 出错率 | 能否自我发现 |
|---|---|---|
| **可手算复核的**（光程、倾角、净空、像素数、遮挡判据） | 低 | **能**（但必须真的去算） |
| **需要空间想象的**（零件连通性、凹槽朝向、旋转符号） | **高** | **不能**（看不到渲染结果） |

**结论：分工必须明确。**
AI 负责算数、判据、参数化；**人负责看渲染图和试打**。
不要指望 AI 自己发现结构错误——除非把它变成可计算的判据（见 §9）。

## 8. 架构演进史

每一版的死因都值得记住，因为它们标记了设计空间的边界。

| 版本 | 架构 | 死因 |
|---|---|---|
| v0.1 | 相机装在表盘正前方 | **误判表盘姿态**（实际朝上，不朝外） |
| v0.2 | 墙面立柱 + 45°镜潜望 | 净空受限方向判断错误 |
| v0.3 | 抱夹进水管 | 阀门到表盘只有 132mm，最长可抱圆柱 30mm |
| v0.4 | 绕表盘轴旋转移开 | **旋转轴正好穿过反射镜，转了等于没转** |
| v0.5 | 径向抽出燕尾 | 燕尾长期蠕变；且 16mm 夹持带需抬 17.5mm，镜片撞天花板 |
| v0.6 | 抱箍与主体融合 | 4 处连通性缺陷 |
| v0.7 | — | 镜面法向符号反了；镜头太低被银圈挡死；镜片槽朝上；LED 被立板挡 |
| v1.0 | 引入 `mirror()` 对称 | 吊臂 hull 生成的是楔形块不是凹槽 |
| v2.0–2.2 | DfAM 重构、T型槽、滑盖 | 天线框越界；LED 座凸出立板 |
| v2.3 | **实物打印** | 托台顶死托板；抱箍尺寸链不闭合 |
| **build123d** | 参数化 + 自检套件 | 自检首次运行即抓到 6 个孤立实体 |

**几个反复出现的教训**：

1. **不要在信息不完整时迭代设计。** v0.1–v0.3 三版全部死于测量数据错误或缺失。
   正确做法是先做一次完整尺寸普查（挑净空最大/典型/最小三台，卡尺量全所有相关尺寸 + 特写照片），
   然后只设计一次。
2. **做加法容易，做减法难。** v2.0 之前一直在为局部问题临时加结构
   （燕尾滑轨、悬臂天线板、方形耳板），从没回头审视整体。
   v2.0 一次性删掉五处冗余，外观和可靠性同时改善。
3. **每个部件都要能回答"没有它会怎样"。**

## 9. 自检套件的设计哲学

`wm_rig.py` 的 32 项自检不是装饰。核心思想有三条：

### 9.1 拓扑检查是最高性价比的

```python
len(part.solids()) == 1
```
一行代码消灭了折磨了十几版的整个错误类别。**任何 CAD 脚本都应该有这一条。**

### 9.2 不只查「不干涉」，还要证明「约束成立」

「A ∩ B = 0」只说明装得进去，不说明装上后不会掉。
所以每个约束都配一条**反向测试**：

| 正向 | 反向 |
|---|---|
| 主体 ∩ 托板 = 0 | 托板下沉 0.5mm **应当**干涉（证明真被托住） |
| 主体 ∩ 滑盖 = 0 | 滑盖前后各推 0.6mm **应当**干涉（证明 Y 向受约束） |
| 托板 ∩ 镜片 = 0 | 镜片外推 1.2mm **应当**干涉（证明唇口挡得住） |

**§7.5 的托台顶死错误，只有反向测试能自动抓住。**

### 9.3 光路做成实体，让遮挡变成布尔运算

```python
cone = light_cone(c)          # 受保护的光锥体
inter_vol(cone, body) < TOL   # 任何结构件进入 = 遮挡
```

把「会不会挡光」从空间想象题变成可计算判据。LED 光锥同理。

### 9.4 现有 32 项分类

```
拓扑        单一连通实体 ×3、is_valid ×3
干涉        主体∩托板、主体∩滑盖、托板∩镜片、开发板∩主体
约束有效性  托板坐实、滑盖限位、镜片唇口
装拆路径    托板提起10、滑盖抽出80、整机抬升17
光路        主光锥∩主体、主光锥∩耳脚、LED光锥∩主体
尺寸链      抱箍过盈、避开凸台、不超银圈顶、容得下双M4
斜面相容    前/后托台低于托板底面、支承脚止于立板前
光学余量    镜片够长、单字符≥20px
装配        开发板落在型腔内
```

### 9.5 尚未实现的检查（欢迎补充）

- **最小壁厚检测**：OCC 里代价很高，目前只靠参数保证 ≥2.5mm。
  若某处布尔运算意外削薄，自检抓不到。
- **打印悬垂角检测**：可以遍历面法线与 Z 轴夹角，标出 <45° 的面积占比。
- **重心/悬臂挠度估算**。

## 11. 协作规范

### 11.1 修改模型的正确流程

```bash
pip install --break-system-packages build123d     # 0.11.1 验证可用
python3 wm_rig.py --check-only                    # 改完先跑自检，约 5 秒
python3 wm_rig.py --assembly --out ./out          # 全通过再导出
python3 wm_rig.py --board my_esp32.step           # 换开发板
```

**任何提交前必须 32 项全绿。** 如果你新增了结构，同时新增对应的自检项。

### 11.2 参数在哪里改

所有尺寸集中在文件顶部的 `Meter` / `Optics` / `Board` / `Mfg` / `Cfg` 五个 dataclass 里。
**不要在建模函数里写魔法数字。**

### 11.3 给下一个 AI 的建议

1. **先读 §7，再动手。** 那些错误机制会重演。
2. **不要相信自己的空间想象。** 把每个几何判断写成可计算的判据放进自检。
3. **看不到渲染结果就明说。** 本项目所有结构性错误都是人发现的，
   假装能看见只会浪费双方一轮。
4. **收到推翻自己判断的数据时，先追问测量语义。**
5. **给出的判据式子要写出来。** "我算过了"不是证据。
6. **做减法。** 每加一个结构，问"没有它会怎样"。
7. **诚实标注置信度。** 可手算的高，需空间想象的低。
