# 变更记录

格式：每个版本记「改了什么 / 为什么 / 谁发现的 / 新增了哪条自检」。
最后一条最重要 —— **每个试打发现的问题都必须先变成一条自检规则**，

## v3.0.0 —— build123d 参数化包 + 110 项自检（本次重构）

### 结构性变化

* 单文件 `wm_rig.py`（824 行）拆成分层的 `wmcase/` 包：
  `params → layout → geometry → parts/refs → model → checks/optics/export/report`，
  依赖方向严格自上而下。
* **所有尺寸集中到 `params.py`**，并按可信度分四类标注
  （`[实测]` / `[采购]` / `[设计]` / `[估算]`）。
* 尺寸链单独成层（`layout.py`），建模和自检共用同一份推导。
* 自检从 32 项扩到 **110+ 项 / 10 个分类**，新增 SEQ（装配顺序）、
  POKA（防呆）、WIRE（走线连通）、DFAM（悬垂 + 壁厚）四类。
* 装配顺序写成数据（`assembly.py`），`ASSEMBLY.md` 由它生成，
  同时也是 SEQ 自检的输入 —— 文档和模型不可能不一致。
* 新增**光路仿真**：虚拟相机 + 逐点光线追踪，产出 `out/sensor_view.svg`。
* 入口统一为 `build.py`（check / build / sim / params / doc / inspect）。

### 第三轮（人工审图，三条现场问题）

| # | 改动 | 为什么 | 谁发现的 |
|---|---|---|---|
| 19 | **建模蓝色固定环 + 蓝色盖板**，镜片 70 → 62mm | 盖板朝墙侧停放时卡住托板后下角。扫描（镜长 × 停放角）得出 62mm 是"光学余量仍有 5mm"和"容忍盖板只翻到 90°"的交点 | 人指出实物有蓝盖 |
| 20 | 抱箍夹紧耳加**六角螺母沉槽**（−X 侧，对边 7.4 × 深 3.6） | 没有沉槽就得双手作业，而现场是站在楼梯上一手扶着整机。六边形顶点朝全局 +Y = 打印姿态的上方，孔顶自收成尖角免支撑 | 人指出 |
| 21 | 板卡加**下缘后压唇** + 改成"抬高 5mm 推入再落下"的装配动作 | 原来 +Y 只靠 EVA 泡棉，而泡棉要等滑盖装上才起作用；在那之前板卡完全自由，一斜就掉 | 人指出 |
| 22 | 装配新增第 0 步：把蓝盖向墙侧翻到底并确认不回弹 | 翻不到位（<90°）托板就装不下去。这是现场唯一需要确认的角度 | 同 19 |

> **第 21 条的关键不是"加了个卡扣"，而是承认卡扣做不出来。**
> 卡钩必须落在 PCB 后表面之后，而唯一能生根的实体是 1.6mm 之外的前止挡台阶 ——
> 没有悬臂长度，弹性卡扣在几何上不成立。改装配动作（抬高→推入→落下）才是解。
> 也评估过"顶部竖直滑入 + C 型槽"，Y 向锁得更死，但要在吊舱顶开 32×8mm 长槽，
> 楼梯间的灰和冷凝水会直接进电子舱 —— 代价大于收益。

> **第 19 条是一条罕见的耦合**：一块**外购玻璃的尺寸**被一个**活动件的姿态**
> 反向约束住了。这种耦合不写进检查（`FIT-14` 扫停放角区间并报出"最小可行角"），
> 就只能等试装才发现。

### 第四轮（卡尺补测蓝色固定环）

用户补了卡尺照片：环内径 56.5、外径 61.8。

* 两个数**完全印证了模型里已有的值** —— 之前从"壁厚 2.65"推出的外径正是 61.8，
  且与独立实测的银圈内径 61.8 吻合。三个数据互相印证。
* 数据来源改正：卡尺量的是两个**直径**，壁厚是算出来的。所以 `ring_od` 改成
  参数、`ring_t` 改成派生量 —— **参数表要照着测量方式写，不能把推导结果当原始数据**。
* 新增 `DIM-11` 盯住"固定环外径 = 银圈内径"，改一个忘了另一个会立刻报错。
* 做了灵敏度扫描，结论是**我之前让人去量的两个尺寸根本不用量**：
  `cover_r` 从 30.9 扫到 36.0、`cover_t` 从 2.0 扫到 5.0，
  最小可行停放角**恒为 90°**。卡住托板的是靠近**铰链**那一端，
  而铰链位置只由 `ring_od` 决定；盖板远端悬在半空够不着托板。
  → 提测量要求之前先跑一次灵敏度分析，别让人白跑。

### 第五轮（实物反馈 + 表头重测）—— **本轮改动最大**

用户给了四条实物反馈。**三条推翻了上一轮的结论**，值得逐条记。

#### 1. 蓝盖还是卡住托板 —— 铰链位置全错

| | 上一版（错） | 实际 |
|---|---|---|
| 铰链 Y | −30.9（固定环**外**缘） | **−28.25**（与固定环**内**圆相切） |
| 铰链 Z | +5.0（贴着环顶面） | **+12.8**（高出环顶面约 5mm） |

铰链往房间侧挪 2.65 + 往上抬 5.0，翻开的盖板整片跟着朝房间侧推进约 **8mm** ——
正好是镜片托板要伸过去的那一段。

> ★ **上一轮的灵敏度扫描结论本身没错，但扫描范围漏了真正敏感的那个量。**
> 扫的是 `cover_r` / `cover_t`（件的尺寸），而决定一切的是**转轴位置**，
> 当时被当成已知量。**扫描能证伪的只有它扫过的维度。**

改动：
* 铰链位置改为派生量（与内圆相切 + 高出环顶 `cover_hinge_above_ring`）；
* 新增 `cover_hinge_tol = 1.0`，**所有让位量按最坏情况算**（铰链再高 1mm）；
* 镜片 62 → **53mm**，并把推导链搬进 `layout.py`
  （`cover_clear_y → holder_rear_cut_y → mirror_y_rear`），
  `Optics.mirror_center_y` 删除 —— 它曾经是"光锥交线取中点"，
  后缘一让中点跟着偏，前缘会**悄悄**不够；
* 托板后端改成一刀**竖直切面**（`build_rear_trim`）：方端面的后上顶点比镜片
  后缘多探出 ≈5mm，正好撞进蓝盖。竖直切之后同样让位量下镜片能多伸 5mm。
  **让零件形状去贴合约束面，而不是整体退让。**
* 托板顶部按 `ceiling_z − 提起行程 − 余量` **主动削平**，DIM-06 从此不可能违反。

#### 2. ★ 新发现的坏消息：翻开的蓝盖会挡掉表盘墙侧一圈外缘

不管铰链多高、停在 90° 还是 105°，翻开的盖板都是一堵立在 y≈−22、
从 z≈11 到 z≈73 的墙。表盘墙侧外缘的光要上行到相机必须穿过它 ——
**镜片做多大、相机放多远都改变不了**。

| | 值 |
|---|---|
| 可见边界 | Y = **−24.15**（最坏情况） |
| 墙侧丢掉 | 约 **4.1mm 半径** |
| 最靠墙的 OCR 要素余量 | **+0.65mm**（`OPT-11-M` 警告中） |

这件事**上一版的自检完全查不出来**，因为遮挡物清单里从来没有水表自己的件。
新增 `OPT-11`（硬判据：OCR 要素必须全部可见）+ `OPT-11-M`（余量 <1.5mm 报警）。

> 想彻底解决只有一个办法：**把蓝盖取下来**（卡在铰链销上的塑料盖，不是铅封件）。
> 取掉后可视半径恢复到 28.25，镜片能加长回 60+。

#### 3. 表头重测：一个 [估算] 值吃掉了 3mm 真实余量

| 项 | 旧 | 新（实测） |
|---|---|---|
| 银圈外径 | 82.1 | **82.2** |
| 银圈高度 | 21.1（手册值） | **24.8** |
| 银圈顶面 Z | +7.0（**猜的**） | **+4.0**（由两条实测推出） |
| 天花板 Z | +77.0 | **+74.0** |

* 抱箍夹持带整段下移 4.5mm（−10~+6.5 → −15.5~+2.0）：
  原来的上沿有 **2.5mm 骑在银圈上方的空气里**，那一段内棱咬不到任何东西 ——
  和 v2.3"夹不紧"是同一类错误，只是这次是被一个 [估算] 的 Z 基准带偏的。
* `glass_depth` 从参数降级为派生量；`ring_h` 5.0 → **7.8**（实测）。
* 顺带修了两条用错量的判据：`OPT-08`（景深 vs 井深）和 `LED-04`（掠射高度）
  都该用 `ring_h` 而不是 `glass_depth` —— 两个数以前碰巧都是"7 左右"，
  分开实测（7.8 / 4.0）之后才看得出用错了哪一个。
* `watermeter-dn25.step` 按 82.2/100.87 **等比缩放**后再摆进装配体，
  人眼审图时比例不再误导（trust 仍是 ILLUSTRATIVE，判定一律只用 `meter_mock`）。

#### 4. 抱箍加**座圈**（内沿圆环）—— 解决 40 台高度不一致

内棱管"转"和"掉"，**管不了"压到多深"**。加一圈架在银圈顶面上的内沿，
压到贴死为止，整机 Z 基准从此和表盘刚性关联。

* 内半径 31.5（> 固定环外半径 30.9，不压塑料环）；
* 径向厚度 9.6 ≤ 银圈径向厚度 10.2（不悬空、不挡光）；
* 墙侧开 ±55° **让位口** —— 蓝盖的铰链凸耳就长在那儿而且**没量过**。
  **面对一个没量过的障碍物，让开它比赌它不存在便宜得多。**
* 新增 `DIM-12`（几何）+ `DIM-13`（反向：再压 0.5mm 必须扎进银圈）。

#### 5. 板卡还是会从 pitch 方向倒出来 —— 而所有 CONS 检查全绿

失效链：板卡能上抬 `board_lift` → 下缘压唇（高 `board_lift − 0.3`）刚好脱开
→ 上端本来就没约束 → 整块板转出去。

> ★ **定理**：用"抬起-推入-落下"装入的板，任何长在壳体上的**刚性**上限位，
> 都不可能把上抬行程限制到小于压唇高度。
> （压唇高度 < 抬升行程 L；上限位离板上缘的距离 ≥ L。两条一联立即得。）
> **与限位放在哪、做多大无关。** 所以只能上弹性件。

> ★ 上一版写的"弹性卡扣几何上不成立"**只对了一半**：结论对，但方向找错了 ——
> 悬臂不必生根在前止挡台阶上。从侧壁沿 Z 长一根 17mm 的悬臂，空间一直都在。
> **"这个方案不成立"要说清楚是哪一种实现不成立。**

改动：两侧各加一根 17×1.6 的弹性悬臂，头上带卡钩（过盈 1.5，锁 +Y）
和顶部压舌（过盈 0.9，锁 +Z，只留 0.4mm 上抬行程）。
悬臂沿**全局 Z** 生长（打印姿态下弯曲应力在层内，不是层间）、朝 **±X** 变形
（垂直于插入方向）。卡钩落在 z 48.9~50.9 —— 板卡背面按 2mm 网格扫过，
**只有**下缘和上缘两段完全没有元件。

`EVA 泡棉`退化成减振垫，不再承担定位职责。
**"重力 + 摩擦"不是约束，写进自由度表里就是自欺欺人。**

### 第七轮（**盖板全部拆除**）

现场试了一下：盖板是卡在铰链销上的，直接掰得下来，**铅封在表体上不在盖板上**。
于是把 40 台的盖板全拆了，表盘上只剩蓝色底环 + 铰链销。

前面三轮为了那堵"翻开的盖板墙"做了一堆事：竖直切面、端壁压到 0.8、镜长
反复在 53/54 之间试、座圈开 ±55° 让位口、判据拆两档……最后被一个"干脆拆了"
一次性解决。

| | 盖板还在 | **盖板拆掉** |
|---|---|---|
| 墙侧最近障碍物 | 翻开的盖板 y=−22.59 | **铰链销前缘 y=−25.40** |
| 可见半径 | 24.88（小盘整圈 **−0.12**） | **27.43**（小盘整圈 **+2.43**） |
| 镜片 | 54mm，光学余量 2.03 | **58mm**，余量 2.45 |
| 托板端壁 | 0.8（玻璃角间隙 0.39） | **1.4**（间隙 0.79） |
| 座圈 | 墙侧开 ±55° 口 | **完整一圈** |
| 警告数 | 3 | **2** |

> ★ **遇到"哪儿都差一点点"的时候，先回头看看约束本身是不是可以去掉。**
> 在自己零件上抠 0.1mm 抠了三轮，不如问一句"这个外购件非留不可吗"。

#### 做法上的几处讲究

* **`Meter.cover_present` 做成开关，不是删掉旧分支。** 万一某台表拆不掉，
  改一个 bool 跑一遍，整条链自动回到带盖板那一套 —— 不用考古"当初改过哪几个数"。
  `DIM-15` 把这个开关和座圈让位口锁在一起（两个有逻辑耦合的参数必须有检查盯着）。
* **铰链销建进模型了**（`refs.blue_hinge`）。销体 z ∈ [7.3, 15.4] 正好横在
  45° 镜面那条线上 —— **"那个零件没了"不等于"那一块空间空了"**。
  `FIT-14` 在无盖板配置下改查它。
* **参数改名** `holder_cover_clear` → `holder_rear_clear`。障碍物是谁会变，
  "托板后端到墙侧最近障碍物"这件事不变。**参数名绑死在某个零件上，
  那个零件一没了名字就开始骗人**（FIT-15 那次就是这么来的）。
* **座圈让位口连换两个理由后删掉**：先是"让开没量过的凸耳"（销量了之后证伪），
  再是"让盖板通过"（盖板拆了之后失效），最后收成 0。
  **保险起见加的东西，等约束清楚了要记得回来收掉。**

#### 三个被这次改动暴露的小坑

| 坑 | 教训 |
|---|---|
| `collar_seat_gap_deg = 0` 时扇形退化成一条线，Polyline 重复点，OCC 直接抛 `BRep_API: command not done` | **"把参数调到 0 就自动关掉这个特征"必须显式写出来**，指望退化几何自己消失，等来的是崩溃而不是空集 |
| 空的 `blue_cover` 进装配体时 `.wrapped` 直接 assert 失败 | 判"有没有实体"要用 `volume`，不能假设空 Part 能一路传下去 |
| `OPT-03B` 原来写成"镜片后缘 vs 蓝盖"，盖板一拆就拿哨兵值 −1e9 去算，报出 +999999972mm | **判据也要能在它所依赖的那个东西消失之后活下来**，否则配置一变就得回来改判据本身。已改写成"可见半径有没有被自己的余量白白吃掉" |

### 第六轮（现场补测铰链 + 指针盘 + 各台盖板开合情况）

六条实测数据，**两条推翻了上一轮刚定下来的东西**。

#### 1. 铰链实测比估读的好，但只有交叉印证过才敢用

| | 上一轮（估读） | 实测 |
|---|---|---|
| 销心高出固定环顶面 | ~5 ±1 | **4.7** |
| 销心高出银圈顶面 | — | **8.3** |
| 销 | — | Ø5.7 × 长 18 |

交叉印证：8.3 − 4.7 = 3.6，与独立实测的"银圈顶→环顶 3.8"差 0.2mm ✓
→ 不确定度 ±1.0 收到 **±0.3**，直接换回约 0.7mm 可见半径。新增 `DIM-14` 盯这条一致性。

> **把不确定度收小是要拿证据换的**，不能因为"现在是实测值了"就自动收小。

顺带证伪了一条设计理由：销体在 z ∈ [9.7, 15.4]，而座圈在 z ∈ [4.0, 6.5]，
**Z 上根本不相交** —— 上一轮"为了让开没量过的铰链凸耳"而开的墙侧让位口，
那个理由不成立了。口保留，理由换成真实的那个（让翻开的盖板穿过座圈平面）。

> **假设被证伪之后，要么去掉那个特征，要么换一个成立的理由 ——
> 不能让特征挂在一个已经不存在的理由上。**

#### 2. ★ 指针小盘实测 → OCR 关键区是 r ≤ 25 的**整个圆盘**

实测：小盘直径 10、盘心到表盘中心 20 → 四个小盘扫过 r ∈ [15, 25] 的圆环。
而**表盘的转向我们不知道**（拧到管路上最后停在哪个角度是随机的），
所以判据必须对任意转向成立。

上一版写死四个猜出来的坐标 `(±14, −8/−18)`。那不但不准，还**恰好避开了
最糟的方位**（正对 LED 那条轴）：眩光判据因此报了个很漂亮的 38°，
按整圈算只有 **21.4°** —— 不及格。

> **用猜的坐标做判据，等于让判据替你挑一个好结果。**

#### 3. LED 位置被迫从 (38,20) 挪到 (39,17)

三条约束互相打架，扫描才找得到可行区：

| pos_r / pos_z | 最小反射夹角 | 掠射高度 | 座孔末端 X |
|---|---|---|---|
| 38 / 20（旧） | 21.4° ✗ | 14.9 | 47.6 |
| **39 / 17** | **27.9°** ✓ | **12.3** ✓ | **48.9** ✓ |
| 40 / 18 | 28.2° | 12.7 | 49.9 ✗ 穿出立板 |

要夹角就得低、要掠过固定环（实测 7.8 高）就得高、要更靠外就把座孔顶出立板。
顺带把灯座凸台 Ø12→Ø10、前端 2.0→1.2（凸台是扶法兰的，不是包灯珠的）。

#### 4. ★ 座圈插进了 LED 的掠射光路 —— 上一轮刚加的东西

座圈内半径 31.5 时，`LED-02` 报有用光束被侵入 **94mm³**，遮挡率 2.4%→4.4%。
座圈在 z ∈ [4.0, 6.5]，而 LED 打向对侧表盘的光正好从这个高度掠过近侧外缘
（光锥外沿 r ≈ 33.8）。内半径收到 **34.5** 之后遮挡率降到 **0.0%**，
比加座圈之前还好；承压环面仍有 ~1570mm²。

> **加新结构件时，除了"会不会撞到别的零件"，还要问"会不会伸进光路 /
> 运动扫掠体"。** 座圈和光路在空间上是错开的两个环带，看渲染图完全看不出来。

#### 5. 可见半径**不是**停放角的单调函数

| 停放角 | 90° | 100° | **110°** | 130° | 150° | 180° |
|---|---|---|---|---|---|---|
| 可见半径 mm | 25.4 | 25.0 | **24.9 最糟** | 25.2 | 26.3 | **29.1 完全不挡** |

现场：每组 6 台里 **2 台**被墙挡住（>90°），**4 台**能翻过 180°。
判定区间因此从 (90,105) 扩到 **(90,180)**，并且必须**扫整段**。

> **只算区间端点会错过这个结论。**

判据随之分两档：主数据（r ≤ 20，余量 +4.9mm）是 ERROR；
小盘最外一圈（r ≤ 25，差 0.12mm）是 WARN。
**用一条判据把两者混在一起，报红时就分不清是"整个盘看不见"还是"边缘少 0.1mm"。**

#### 6. 镜片端壁会遮住镜片自己的后缘

射线追踪报"小盘外缘被镜片托板挡住"。查下来：光线是**斜着**进 T 型槽的，
它穿过唇口平面的位置（局部 y=27.68）比落到镜面上的位置（26.47）更靠后 ——
正好落在深槽后端（27.10）之后的端壁上。

修法：让**开口**比**深槽**再往后长 4mm。深槽后端face 是镜片的止挡，必须留；
唇口那 0.8mm 一层在镜片后缘之后没有用，留着只会挡光。

> **只看"落点在不在镜片上"会漏掉这一段。**

镜片同步 53 → **54mm**，托板端壁 0.8 → 1.0（`FIT-15` 的真实间隙回到 0.39mm）。

### 这一轮暴露的检查问题（五个，全部已修）

| # | 问题 | 教训 |
|---|---|---|
| 1 | 遮挡物清单里从来没有**水表自己的件**（蓝环、蓝盖） | 遮挡判据的可信度上限 = 它的遮挡物清单的完整度。`LED-05` 的说明里甚至写着"环会投下阴影，本条逐点验证"，而环根本没进过清单 —— **文档写了『自检会验』不等于自检真的在验** |
| 2 | `CONS-14` 只做**平移**试探，测不出**转动**自由度 | 板卡 +Y 平移被压唇挡住 → 通过；但它可以绕压唇转出去。**平移试探测不出转动自由度** |
| 3 | `CONS-16` 初版用"固定角度下的干涉体积"，3° 只有 4.4mm³（容差 2.0），且 **5° 反而只有 1.8mm³** | 板卡上缘已经转到卡钩**后面**去了。**"推得越狠干涉越大"对有限尺寸的挡块不成立。** 改成扫角度找"第一个被挡住的角度"，读数还有物理意义 |
| 4 | `DIM-13` 初版把探针方向写反（抬水表而不是压整机），永远量到 0 | **反向判据的方向写反不会报错，只会安静地永远通过。** 必须做一次"去掉被测特征后它会不会红"的负向验证 |
| 5 | `LED-05` 的"每点两灯可达"在补全遮挡物后**物理上不可能满足** | **一条永远满足不了的判据比没有判据更糟**，它会训练出"忽略红字"的习惯。拆成"任何点不许全黑"（硬）+ "OCR 区两灯可达"（警告） |
| 6 | `holder_cover_clear = 0.8` 加在托板切面上，而真正离蓝盖最近的是**玻璃的后-背角**（真实间隙 0.39mm） | **"标称间隙"和"真实间隙"往往不是同一个量。** 参数名要说清楚它是谁到谁的间隙。新增 `FIT-15` 把真实的那个点算出来 |
| 7 | `DFAM-02` 把 45° 棱边和 0.45mm 的**刻字笔画**都当成"薄壁"报出来 | 壁厚只有在**两个面近似平行**时才有定义（已加出射法线过滤）；刻字是表面标记不是壁，量之前先填平（`Design.thickness_probe_parts`）。**靠调高阈值容忍已知噪声 = 把检查的分辨率一起调没了** |

**顺带修掉的两个几何缺陷**（都是这轮新加的东西带出来的，也都是自检抓的）：

* 竖直切面正好落在托板端部的 R2 圆角里，切出 **0.15mm 的羽边** ——
  后端先补一段方料再切。**在一个要被切掉的端面上做圆角是白做的。**
* 提手顶面写死 64，而削平面算出来也正好 64 —— 两个面严丝合缝重叠，
  布尔留下一圈退化三角形。提手高度改成跟着削平面走（低 1mm）。
  **共面的布尔要么留重叠，要么留间隙，就是不能正好相切**（`TOPO-04` 的老教训又来一次）。

**负向验证做了**：注释掉弹性卡钩后 `CONS-16` 报"扫到 4° 仍无干涉 —— 这个方向
**没有约束**"、`CONS-17` 报 0，而老判据 `CONS-14` **依然通过** ——
和实物表现完全一致。**没红过的检查不能算数。**

### 这一轮又暴露的两个检查问题

* `TOPO-04`（上一轮才补的网格化检查）**立刻抓到**压唇和导轨只重叠 0.01mm、
  又和承台正好相切造成的退化边 —— 补的规则马上还了本。
* `OPT-03` 的余量 5.0 是硬编码的，而镜长上限被蓝盖卡在正好 62.0 = 57.0+5.0，
  浮点误差让它在 `62.0 >= 62.00000000000001` 上翻脸。
  **判据卡在自己设的阈值上时，要么留数值容差，要么说明为什么正好卡着。**

### 检查本身的三个漏洞（第 16 条暴露出来的）

1. **`LED-01` 只和 `body` 求交，从来没和 `mirror_holder` 求交过** ——
   而挡光的恰恰是托板的支承片。
2. **把灯珠当成点光源。** 点光源追踪 0% 被挡，按真实 Ø5 穹顶取 9 个发光点
   追踪 46% 被挡。**判据的分辨率不够时，它给出的"通过"毫无意义。**
3. **`need_half_angle_deg` 是手填的 21°。** LED 从 z=30 降到 20 之后它没跟着变，
   而几何上真实需要 41.1°。已改成派生量 —— **凡是能由几何唯一确定的量，
   都不许出现在参数表里。**
4. **`LED-02` 在灯珠周围挖的排除球开到了 Ø14**，正好把证据一起挖没了。
   **排除区域开得太大，等于把检查关掉。**

现在 `LED-01`/`LED-02` 都验证过：去掉让光拱会分别报 46% 遮挡和 62mm³ 干涉。

### 工具坑（都值得记住）

* **`import_step` 返回的嵌套 Compound 直接做布尔会静默返回空集。**
  `body & board` 恒等于 0，所有关于开发板的干涉检查一起"通过" ——
  最危险的假阴性。修法：`refs.load_step_fused()` 先把实体熔成一个 Part。
  发现线索：三条互相独立的检查（板卡 −Y/±X/−Z 约束）同时报出同一个可疑的 0。
* **反向判据的阈值必须比正向容差高一个量级**，否则那条检查是假的。
  LED 极性防呆的干涉体积不到 1mm³，而"不干涉"的容差是 2mm³ ——
  只能改用**线性阻挡量**做判据。
* **反向判据的方向要想清楚。** `POKA-01`（托板调头）第一版写成"应当干涉"，
  而实际失败模式是"会悬空"，判据方向完全相反 —— 那条检查永远为假。
* **不要为了做碰撞检测先把场景 union 起来。** union 本身就是最贵的布尔，
  逐个求交再相加结果一样，但快两个数量级（20 分钟 → 20 秒，内存 3GB → 正常）。
* **`Axis` 求交返回的是整条直线的交点**（包含反向），必须自己按参数 t 过滤。
* **STEP 合法 ≠ 网格合法**，而切片器吃的是网格。`is_valid=True` + `solids==1`
  + 干涉全过 + STEP 正常导出，网格化照样可能失败。
  推论：**两个减法体不要只在一个平面上相切**，宁可让它们有几毫米体积重叠。
  已补成自检 `TOPO-04`。

### 还没做的

* 桥接跨度没有自动检查（靠切片预览）
* 壁厚 / 悬垂是**采样**，不是证明
* `esp32s3cam-1` / `-3` 还没适配（第一版只适配 `-2`）
* 蓝盖翻开停放的位置仍是估算 —— **当前风险最高的一条未验证假设**（`FIT-14`）
